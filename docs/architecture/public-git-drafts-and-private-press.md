# 公開Git下書きの残余リスクとprivate案件サイト

## 方針

**通常のXpotato記事は公開GitHubの編集ブランチ + Draft PR + GitHub Actionsを標準制作経路とする。**

目的は、公開repositoryのGitHub-hosted Actionsの無料枠・サーバー不要のCI、PRで人間が執筆してAIへ未完了の監査/修正を引き継げること、同じPRへ追pushしながらレビュー・検証・修正履歴を追跡できること。通常の一般技術記事は機密ではないため、サイト公開前にGitHubのソースが閲覧可能でも許容する。

**公開GitHubでの検索露出は明示的に受容する残余リスク**。通常の検索で公開記事よりPRが目立つとは予想しないが、個々のPRがインデックスされない/検索上位に来ない保証はない。公開GitHub側にnoindexを設定できると仮定せず、クロール回避のために複雑な別経路を標準へ追加しない。

改稿前の文章は旧PRだけでなくGitのコミット履歴にも残る。これを無理に消すために履歴改変/PR削除を通常運用へ入れない。旧PR・古い本文を歴史的記録として扱い、**正式な最新情報の責務は本番サイトだけ**が持つ。必要に応じてPRの冒頭に「作業中/旧稿」と示し、公開後は公式記事へのリンクを追加できるが、全過去PRを編集するための継続作業は要求しない。

## 二つの独立した状態

| 判断軸 | 状態・意味 |
| --- | --- |
| 制作物の公開範囲 | `public_git`（通常の標準） / `private_workspace`（本当に機密性が必要な場合） |
| サイト掲載/審査 | `draft`・`review`・`approved`・`published`（具体的な実装は既存Article Job/Publication契約と整合させる） |

`draft: true`、RSS/検索/sitemapの除外やサイトのnoindexは、**Xpotatoサイトで未承認記事を配信しないための仕組み**であり、GitHub上の機密性を提供しない。正式サイトでは未承認の本文を掲載・推奨・OGP配信しない。公開GitのDraft PRから制作途中の文を読む人がいる可能性は許容する。

### 人間 → AI → PRの継続作業

1. CMSで既存内容を指定ブランチから読み込み、記事ContentIdと作業branch/base commitを固定して人間が執筆する。
2. 公開Gitを選んだ場合は、初回push時のみ「ソースおよびPR履歴は第三者に閲覧可能」と提示する。作業MDXは`draft: true`として通常のDraft PRへ保存する。
3. AIが同じPRとContentId、原稿、レビュー指摘を読み取り、未完了の整形・構成・出典・監査・図版の作業を引き継ぎ、同branchへ追pushする。人間制作部分とAIが実質的に追加した部分の来歴は正確に扱う。
4. GitHub CIでソース/参照/プレビューの公開安全な部分を検査し、人間が品質を確認する。**未審査画像・GPSを含むHEICや権利未確認の素材は、原稿がpublic GitでもPrivate Draft R2に置ける**。公開PRのsource、Actionsログ、artifactに秘密URLや画像bytesを出さない。
5. 承認・媒体のA/B/C実保存照合・正式export・CI・本番配信でのみpublishedへ移す。Draft PRのClose/Ready/Mergeだけで公開完了としない。

## privateリポジトリによる案件・プレスページ

受注案件、未解禁の製品情報、プレスリリースで秘密保持が必要な場合は、**制作初期から別のGitHub Private repository**を使う。将来は`press.xpotato.net`等のサブドメインを候補とし、本サイトのメニューから発表済みページをリンクできるようにする。これは将来構想であり、現在の実deploymentやrepository作成を意味しない。

- 見た目は本サイトに合わせるが、Astroサイト全体を手動コピーして常時二重保守するより、固定versionの共通design-system/部品・テンプレートを再利用する。press固有の本文、meta、権利、サイトマップ、公開承認と解禁日をprivate側が所有する。
- Public GitHub Actionsの無料性はprivateリポジトリへそのまま移らない。private Actionsの無料付与枠と使用料/公開用ビルド頻度を別途評価する。
- **Private repoでも、実際に配信したプレビュー/HTML/画像まで自動で非公開にはならない**。解禁前プレビューはCloudflare Access等の認証で保護する。noindexだけで機密性を保証しない。
- 公開時は内容・権利・公開解禁時刻（タイムゾーン）を確認してから配信し、正式公開後に本サイトのメニューへリンクする。非公開資料やsecretを共通テンプレート/公開Gitへ流用しない。

## 判断と境界

通常記事では公開PRの検索上露出や、旧PRが旧内容を残すことを**許容済みのトレードオフ**とする。理由はその想定される実害より、無料CI・PRによる人間/AI協働・履歴保持の利点が大きいため。これは検索非表示の保証でも、秘密保持対象の公開許可でもない。

機密/個人情報/契約上の非公開資料は、**最初からpublic Gitにpushしない**。後からbranchやPRを消しても取り戻せないため例外ではない。画像媒体の非公開管理と、原稿のGit可視性は別々に判断する。

本書は制作ワークフローの設計方針。private repo/pressサブドメイン/アクセス制御/R2/公開配信の実設定変更を許可しない。
