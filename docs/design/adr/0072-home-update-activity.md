# ADR-0072: ホームの更新ストリップ

PR179の段階1の実装候補。本番配信や段階2の実装を認可しません。

## 記録の出所と限界

共通frontmatterには既に `pubDate` と任意の `updatedDate` があり、記事・メモ・ツール・制作物で共用できます。公開catalogから公開日と、それより新しい最新更新日を1件ずつ抽出します。同日の公開と更新は二重計上しません。1コンテンツの全改訂履歴ではなく、現在保存されている記録の集計です。過去の複数回更新は復元しません。アーカイブ済み制作物の公開履歴も残し、非公開・noindex・保留データは数えません。日付を見栄えのために変更しません。

`updatedDate` は内容を実際に改訂した日に著者側の正規の編集工程で更新します。Gitコミット日時、build日時、表示時刻は代用しません。日付だけでも可能な経過時間の上限が72時間以内ならNEWと確定できます。正確な時刻が分かる場合は任意publishedAt/updatedAtを記録します。完全な追記型更新ログは別途検討し、日付だけの旧記録へ時刻を補いません。

共通 `UpdateEvent` は `id / contentId / date / occurredAt? / kind / action / title / route`、週モデルは月曜の日付 `id / counts / events / total / level / current / beforeLaunch / launch` を持ちます。`occurredAt` は任意のpublishedAt/updatedAtから生成します。任意日時のschema・著者入力は今回追加します。完全な履歴ログの永続化は別判断です。

## 時間と表示

JST固定の月曜始まり、今週を含む13週です。ブラウザ時計を渡す純粋関数で集計します。端末の時間帯は参照しませんが、端末時計自体が誤っている場合の補正はしません。未来日、未来時刻、不正日、日付とJST日時が矛盾する記録は集計から除きます。NEWは明記された日時に対して0〜72時間（端点を含む）、日付だけなら可能な経過時間の上限が72時間以内の場合に表示します。未確定は表示しません。日数はJST暦日差で、0日を今日、1日を昨日とします。

静的HTMLは絶対日付とツール・制作物の最新リンクを表示します。週窓をbuild時に描かず、スクリプトが使えない時に現在の週と誤認させません。初回とJSなしは同じHTMLで、マウント後に差し替えます。表示中は1分ごと、ページ復帰時も再計算し、長期間開いたタブに古い週・NEW表示を残しません。

全体件数、各週の種別別代替テキストとtooltip、右端下の今週の紫の三角を併用します。マス内の数字、今週の輪郭、週単位の新着強調は表示しません。NEWは個々の項目へ付け、読み上げ用の「新着」を持ちます。animationは使いません。更新停止時の非表示ポリシーは決めず、経過日数と空の週を正直に表示します。

## 実行時の境界

ホームはReactを読み込んでいません。静的HTML優先の既存方針に合わせ、通常のAstro部品を依存のない単一moduleで拡張する案を採用します。React Island案との転送量は比較ビルドで確認します。ホームの部品と一対一のscriptだけを許可し、raw 8000 bytes / gzip 3000 bytesの上限、依存・network・storage・動的codeの禁止を検査します。他の通常ページのJS予算は広げません。

検証用の疎な3件・8週以上の停滞・日時付き直近更新・未来/不正日は `tools/qa/` のfixtureから生成します。公開catalogや通常distには入れません。本人限定プレビューへ追加する場合も実記録でないことを明記し、通常ホームとURLを分けます。

## 段階2で再利用するもの

週ID・種別件数・イベント配列をそのまま `/updates/#2026-11-09` のような1ページ内アンカーと種別フィルターに利用できます。W番号や週別ページは不要です。今回、リンク・フィルター・履歴routeは作りません。段階2では更新のない週を非リンクとし、モバイルの幅24px以上と縦のタップ領域を確保する別レイアウトを追加します。

履歴の欠落を避けるには、段階2で追記型ログを採用するか、現在の「公開日＋最新更新日」だけを表示するかを先に決めます。最新更新日だけから完全な履歴を装うことはしません。

## 比較ビルドの観測（2026-11-12）

Node 24.22.1 / Astro 7.2.8 / React 19.2.8で、同じ日付モデルと13週描画・時計更新を持つ比較用Islandを既存build設定で生成しました。通常ホームの素moduleは4,160 bytes（gzip 2,054 bytes）。React案はcomponent・共通日付model・React・renderer合計195,330 bytes（gzip 62,313 bytes）、別にAstro inline起動scriptが4,510 bytesありました。gzipは各assetをnode:zlibの既定設定で圧縮した合計で、HTTP実測ではありません。共通イベントpayload・CSS・HTML・通信headerを除くcold-cache比較です。既に別ページのReactをcacheしていれば差は小さくなりますが、ホーム初回にそのcacheは仮定しません。

## 旧比較の記録（2026-11-12、後続の構造改訂で上書き）

公開週は `update-policy.ts` の1か所に `2026-10-05` として設定します。11月12日時点の「公開から6週」という指定に対応するJSTの月曜です。これは公開日の時刻を示す値ではありません。列増加案は撤回し、常に今週までの13週を表示します。公開前は透明な点線枠、公開後0件は薄い塗りで区別します。要約は常に「直近13週でm件」です。公開前の記録は集計から除き、週モデルの `beforeLaunch / launch` で公開前と公開週を区別します。公開後13週が経過すると公開前のマスは窓の外へ出ます。

固定値は移行記事の過去日付、記事削除、非公開化、更新日の訂正でサイトの年齢が変わらない利点があります。一方、公開週の正確な設定を人が管理する必要があります。最古の更新日からの自動算出は設定不要ですが、コンテンツの履歴とサイト公開時期を混同し、対象データの変更で始点が動くため採用しません。

帯は先頭にサイト全体の最終更新、その隣に種別とツール・制作物の最新リンクを置きます。記事が最新の場合も記事リンクへ差し替えず、両者の対象と日付を読み上げ説明・tooltipで区別します。通常サイズは1行、題名のみ省略します。200%文字などで全情報が収まらない場合は、可読性のため帯を折り返します。

帯／月ラベルを含むストリップ／小さな要約の3段構成です。13列を本文幅いっぱいに均等配置し、各列の領域は最小24px、内側左右1pxずつで見た目の間隔2pxを作ります。バーは14px高、角丸2pxです。320pxではストリップだけ本文の左右余白へ出し、316pxの領域を中央寄せします。この場合の可視バー幅は22pxですが、列の領域は24pxです。可視バー24pxと独立した2px gapを両方確保すると336px必要になり、320pxに収まらないためです。段階2では列幅を保持し、各列の非重複な領域を高さ44pxへ広げて中央に14pxバーを置く設計とします。段階1のタップ要素は作りません。

最終更新は本文色・太さ600・.875remで主役にし、題名.8rem、種別.7rem、補助要約.65remの順にします。帯とストリップ、ストリップと要約は.35remの間隔です。直後の記事セクションの上余白を2.5remから.5remへ詰め、要約と区切り線の空白を減らします。文字拡大時の折返しは維持します。

「公開」ラベルは公開週のバー下へ月ラベルと同じ文字サイズで置く比較案です。通常はラベルなしとし、本人限定の `current-labeled` 例だけ属性で表示します。点線から塗りへ変わる理由を視覚的に説明できる一方、公開から13週までの短期間だけ1行増え、静かな3段構成からは離れます。どちらの表示でも公開前・公開週を各週の読み上げとtooltipに含めます。公開前の点線の意味が伝わるならラベルなし、初見で境界を明示したいならありを選べます。現時点では比較用で、採用決定ではありません。

本人限定プレビューとQAには公開から6週で9件、13週を超えたスライド、8週以上停止の別fixtureを用意します。通常データの公開週や更新日を検証用に書き換えません。JS無効の実ブラウザ検査に加え、配信する静的表示例はscript要素を除去し、静的表示の例であることを明記します。

13週固定・公開前表示への改訂後の素moduleは5,389 bytes（gzip 2,507 bytes）です。上記React比較は初期版の観測であり、今回のUIをReactで再測定した数値ではありません。raw 8,000 / gzip 3,000 bytesの予算内で、依存やネットワーク通信は追加しません。

## 固定見出しと項目単位NEWへの改訂（現行候補）

上記の1行帯、サイト全体の相対日付、今週の輪郭、週単位48時間強調、最小316pxのはみ出し配置は撤回します。現行は「更新状況」のh2／ツール・制作物の最新1件／月ラベル・13週・△／要約です。h2は他セクションと同じ明朝、サイズ、見出し枠を使います。将来の「更新履歴 →」は既存の一覧リンクの型で見出し右へ置く設計だけを残し、段階1ではリンクや行き先を作りません。

最新項目は上段のメタ情報（NEW、JST暦日差、種別・公開/更新）と下段の題名・矢印に分けます。メタは同じ小さい文字サイズ、題名はゴシックの1remで、記事カードのメタ→題名という型に揃えます。両段とも折返しを許し、高さを圧縮しません。日付はリンク先のツール・制作物自身に統一し、記事がサイト全体の最新でもこの対象は変えません。

NEWは単一の isNewUpdate を使い、同じcontentIdの最新項目・記事カード・ツール・制作物で共通です。時差付きoccurredAtを優先し、日付だけならJST日の最早境界からの経過時間を上限として計算します。0〜2日前は時刻がなくても72時間以内です。3日前は通常未確定ですが、JST午前0時ちょうどだけは端点を含む72時間以内で、1ms後には非表示になります。境界を実時刻として保存せず、日付やoccurredAtを書き換えません。不正・未来・矛盾した明示日時を日付精度へフォールバックしません。ストリップにはNEWや最近更新の輪郭を付けません。

ストリップは本文左端から幅100%、最大520px。13列は常に等分です。320pxの本文幅へ13×24pxが収まらないため、本人の可変指定に従い固定24pxを撤回し、本文の左右端に収めます。バー14px、内部の見た目の間隔2px、角丸2pxを保ちます。公開前の連続範囲には1本だけ点線を重ね、週ごとの透明な読み上げ領域は保持します。公開後0件は #e5dced、1件 #d0b4e5、2件 #a780c5、3件以上はブランド紫。境界や濃淡だけに依存せず、各週の正確な内容を代替テキストとtooltipへ残します。

今週は右端列の中央下に10×9pxの塗り三角を置き、「今週」の代替テキストを持たせます。文字と輪郭はありません。静的HTMLでも三角は同じ位置です。ただし静的な13個の補助線は未集計であり、0件を示すものではないと明示します。週日付や件数をbuild時に固定しません。JSなしは絶対日付・見出し・リンク・三角が読み取れ、NEWは出ません。

### フォント点検と是正

- 更新見出しが存在しなかった点をh2＋共通section-headingへ変更しました。
- 旧相対日付・種別は本文の継承で、PROJECTと異なっていました。日付・月・NEW・種別・PROJECTはhome-metaと既存font-metaを使います。
- 新着記事・ツール・制作物の題名は既に共通font-bodyでした。ホーム内の題名役割を明示して維持し、明朝だったとの初期推測は採用しません。
- 要約の日本語は小さいfont-bodyを維持し、「13」「件数」の数字だけfont-metaで共通の字形にします。日付・数値はtabular-numsを使います。
- 記事の公開日とfooterのソース改訂は既にfont-metaで、変更しません。ヒーローの英語displayは固有表現、ナビゲーションは操作文字として維持します。
- font-metaはOSの等幅フォントを先頭にし、日本語は既存Zen Kaku Gothic New等へfallbackします。異なるOSの字形完全一致は保証せず、同一画面の役割と数字の指定を統一します。Webフォントファイルの差替えはしません。

公開ラベルあり/なしは引き続き比較だけで採用未決定。長期停止時の非表示、ツール行リスト化、カルーセル変更、セクション順は決めません。段階2は週データを再利用できますが、狭幅で13個の横24pxや44px正方形を同時に確保することはできません。タップ時は非重複44px高さや対象のまとめ方を別途設計し、今回クリック要素を追加しません。

### 検証用状態と証跡

currentは公開から6週・最新2日前の時刻付き記録、four-daysは同じ9件で最新4日前、slidingは公開19週で直近13週の9件、stalledは65日前以降記録なし。date-onlyは2日前の日付だけでもNEWを出す例、date-only-three-daysは3日前が未確定になる例です。記事・ツール・制作物の実在するcontentIdに合成イベントを結び、3種の表示へ同じNEW判定が適用されることを検査します。実際の内容を更新したという意味ではなく、すべて検証用であることを表示します。通常catalogやdistに合成データを出しません。

320/390/1487px、200%文字、月境界、JST、JS無効、72時間境界、未来/不正/日付のみを検査します。モバイル初期表示で新着記事h2の矩形を取得し、viewport内に収まるか否かを記録します。画面が低い場合に必ず収めるための圧縮は行いません。幅、三角、フォント、記事見出し位置、区切り線余白をaxe artifactのupdatesReportにも保存します。実測前の値を測定結果として記述しません。

### 正規入力経路

任意publishedAt/updatedAtをBlog/Notes/Tools/Projects frontmatterとcatalogへ追加し、ホームのoccurredAtへ伝えます。CI公開時も明記した値を保持し、日付変更による矛盾と未来時刻を拒否します。既存記事には値を追加していません。記入・承認・更新区分の規則はblog-frontmatter-contract.mdのDate節に集約します。

同日公開・更新は、閲覧時計で未来・不正なイベントを除いてから1件にまとめます。端末時計が更新時刻より前でも、既知の公開は残ります。内容更新で前回と同じupdatedAtを流用する場合は、新しい正確な時刻の入力または削除を要求します。metadata_only/media_onlyは既存日時を保持します。

現行候補の素moduleは5,934 bytes（gzip 2,720 bytes）です。前掲Reactの数値は初期版比較であり、現行UIをReactで再実装した差分ではありません。gzipはnode:zlibの既定圧縮で、実HTTP転送量ではありません。
