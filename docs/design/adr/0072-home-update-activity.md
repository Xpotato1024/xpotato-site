# ADR-0072: ホームの更新ストリップ

PR179の段階1の実装候補。本番配信や段階2の実装を認可しません。

## 記録の出所と限界

共通frontmatterには既に `pubDate` と任意の `updatedDate` があり、記事・メモ・ツール・制作物で共用できます。公開catalogから公開日と、それより新しい最新更新日を1件ずつ抽出します。同日の公開と更新は二重計上しません。1コンテンツの全改訂履歴ではなく、現在保存されている記録の集計です。過去の複数回更新は復元しません。アーカイブ済み制作物の公開履歴も残し、非公開・noindex・保留データは数えません。日付を見栄えのために変更しません。

`updatedDate` は内容を実際に改訂した日に著者側の正規の編集工程で更新するのが最小案です。Gitコミット日時、build日時、表示時刻は代用しません。現データは日付だけなので、48時間以内とは断定しません。将来の記録に日時を追加する場合は、ContentIdに結び付いた追記型更新ログに時差付き `occurredAt` を保存する案を別途検討します。日付だけの旧記録へ時刻を補いません。

共通 `UpdateEvent` は `id / contentId / date / occurredAt? / kind / action / title / route`、週モデルは月曜の日付 `id / counts / events / total / level / current / recent` を持ちます。`occurredAt` はまだfrontmatterから生成しません。実際のschema・著者入力・履歴の永続化は別判断です。

## 時間と表示

JST固定の月曜始まり、今週を含む13週です。ブラウザ時計を渡す純粋関数で集計します。端末の時間帯は参照しませんが、端末時計自体が誤っている場合の補正はしません。未来日、未来時刻、不正日、日付とJST日時が矛盾する記録は集計から除きます。48時間は明記された日時に対して0〜48時間（端点を含む）だけ強調します。日付だけの記録は非強調です。日数はJST暦日差で、0日を今日、1日を昨日とします。

静的HTMLは絶対日付とツール・制作物の最新リンクを表示します。週窓をbuild時に描かず、スクリプトが使えない時に現在の週と誤認させません。初回とJSなしは同じHTMLで、マウント後に差し替えます。表示中は1分ごと、ページ復帰時も再計算し、長期間開いたタブに古い週・48時間表示を残しません。

全体件数、各週の種別別代替テキストとtooltip、今週の紫の輪郭を併用します。マス内の数字は表示しません。48時間の強調は二重線と読み上げ説明で、animationは使いません。更新停止時の非表示ポリシーは決めず、経過日数と空の週を正直に表示します。

## 実行時の境界

ホームはReactを読み込んでいません。静的HTML優先の既存方針に合わせ、通常のAstro部品を依存のない単一moduleで拡張する案を採用します。React Island案との転送量は比較ビルドで確認します。ホームの部品と一対一のscriptだけを許可し、raw 8000 bytes / gzip 3000 bytesの上限、依存・network・storage・動的codeの禁止を検査します。他の通常ページのJS予算は広げません。

検証用の疎な3件・8週以上の停滞・日時付き直近更新・未来/不正日は `tools/qa/` のfixtureから生成します。公開catalogや通常distには入れません。本人限定プレビューへ追加する場合も実記録でないことを明記し、通常ホームとURLを分けます。

## 段階2で再利用するもの

週ID・種別件数・イベント配列をそのまま `/updates/#2026-11-09` のような1ページ内アンカーと種別フィルターに利用できます。W番号や週別ページは不要です。今回、リンク・フィルター・履歴routeは作りません。段階2では更新のない週を非リンクとし、モバイルの幅24px以上と縦のタップ領域を確保する別レイアウトを追加します。

履歴の欠落を避けるには、段階2で追記型ログを採用するか、現在の「公開日＋最新更新日」だけを表示するかを先に決めます。最新更新日だけから完全な履歴を装うことはしません。

## 比較ビルドの観測（2026-11-12）

Node 24.22.1 / Astro 7.2.8 / React 19.2.8で、同じ日付モデルと13週描画・時計更新を持つ比較用Islandを既存build設定で生成しました。通常ホームの素moduleは4,160 bytes（gzip 2,054 bytes）。React案はcomponent・共通日付model・React・renderer合計195,330 bytes（gzip 62,313 bytes）、別にAstro inline起動scriptが4,510 bytesありました。gzipは各assetをnode:zlibの既定設定で圧縮した合計で、HTTP実測ではありません。共通イベントpayload・CSS・HTML・通信headerを除くcold-cache比較です。既に別ページのReactをcacheしていれば差は小さくなりますが、ホーム初回にそのcacheは仮定しません。

## 公開週と表示の改訂（2026-11-12）

公開週は `update-policy.ts` の1か所に `2026-10-05` として設定します。11月12日時点の「公開から6週」という指定に対応するJSTの月曜です。これは公開日の時刻を示す値ではありません。公開前の週は表示せず、1〜12週は「公開からn週でm件」、13週目以降は今週までの13週と「直近13週でm件」を使います。

固定値は移行記事の過去日付、記事削除、非公開化、更新日の訂正でサイトの年齢が変わらない利点があります。一方、公開週の正確な設定を人が管理する必要があります。最古の更新日からの自動算出は設定不要ですが、コンテンツの履歴とサイト公開時期を混同し、対象データの変更で始点が動くため採用しません。

帯は先頭にサイト全体の最終更新、その隣に種別とツール・制作物の最新リンクを置きます。記事が最新の場合も記事リンクへ差し替えず、両者の対象と日付を読み上げ説明・tooltipで区別します。通常サイズは1行、題名のみ省略します。200%文字などで全情報が収まらない場合は、可読性のため帯を折り返します。

帯／月ラベルを含むストリップ／小さな要約の3段構成です。13個分の24pxセル領域を常に確保し、経過週数によって伸縮しません。各セル内の22pxの塗り面の間に2pxの余白ができ、枠は当週・48時間内だけに使います。320pxでも24pxのセル領域を確保するため、ストリップだけ本文の左右余白へ出し、316pxの全幅を中央寄せします。段階2の操作要素は未実装です。

本人限定プレビューとQAには公開から6週で9件、13週を超えたスライド、8週以上停止の別fixtureを用意します。通常データの公開週や更新日を検証用に書き換えません。JS無効の実ブラウザ検査に加え、配信する静的表示例はscript要素を除去し、静的表示の例であることを明記します。
