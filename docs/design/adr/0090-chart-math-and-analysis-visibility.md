# ADR-0090: 数式表示と解析情報の公開粒度

## 背景

近似式、正規化座標、丸め前の係数を同一の二段組みで表示すると、スマートフォンでは折り返しや長い数値が説明の妨げになる。一方、計算の再現性を確保するため、詳細を削除せず切り替え可能にする。

## 判断

- 保存する測定点・理論式・近似条件・表示設定を分離する。
- `analysisDisplay` は `concise`（既定）・`detailed`・`hidden` の三状態。非表示でもグラフの曲線・データ表・元の計算は維持する。
- `concise` は折りたたみ内にTeXから生成した静的MathMLとR²・RMSEのみ表示する。`detailed` はさらに入れ子の折りたたみに正規化座標、丸め前の係数、点数・範囲・注記を追加する。
- TeXは検証済みの数値および限定式ASTから生成し、任意の著者入力TeXを処理しない。公開記事に追加のJavaScriptやWebフォントを必要としない。
- 小さい画面では数式のみ横スクロールし、計算情報は縦積みとする。長い数値は無理に折り返さない。

## 検証

正しい数式変換と演算子優先順位、静的MathML、三つの表示モード、rawデータと解析の不変性、MDXとプレビューの一致、スマートフォン幅での表示、全CIの成功を確認する。

## ページ別容量と読み込みの決定

公開記事の数式は、既存の本文数式と同じKaTeXでビルド時にMathMLへ変換し、読者へ数式ランタイムを送らない。グラフ・測定点とともに静的HTML/SVGで提供する。複雑な数式・グラフ・ブラウザツールが共存するページでも、インタラクティブな機能に必要なコードだけをページ／機能単位で読み込む。

CMSでは入力検証用 `charts-core.ts` を静的な経路に置き、KaTeXを使う `charts.ts` はグラフプレビューや適用操作で遅延読み込みする。`LineChartPreview` 自体も遅延読み込みとする。これにより、通常の編集開始時に数式描画エンジンまで取得しない。

性能予算はページ種別と読み込み段階で分ける。CMSの初期JS上限（raw 1,000,000 / gzip 320,000バイト）と全機能を含むJS上限（raw 3,400,000 / gzip 1,100,000バイト）は維持し、CIで両方を検査する。ツールや高機能記事の上限を変更する場合は、代表端末での実測と新しいADRを根拠とし、一律の緩和を行わない。

## 多機能CMSの依存関係と容量制限

- 数式表示には既存のKaTeXを使用する。近似式・理論式のTeXは共通描画側で静的MathMLへ変換し、公開ページへ数式ライブラリの実行コードを追加しない。
- 編集画面では軽量な数式メタデータ解析とKaTeXを切り離す。コードブロックのメタデータ編集だけで数式エンジンを初期読込しない。
- グラフ本体はReact.lazyで必要になってから読み込み、グラフ設定適用時の検証と記事プレビューも動的importを用いる。記事にグラフが存在しなければ、プレビューはグラフ描画コードを読み込まない。
- 初期読込と機能を使用した際の追加読込を分離して性能評価する。既存の初期JavaScript上限（非圧縮1,000,000B／gzip 320,000B）をグラフ追加のために緩めず、機能別チャンクにより達成する。追加の3D・解析・ブラウザツールでも同方式を優先し、必要であれば個別の利用時予算を設ける。
- 依存の増加を隠すために数式の対応範囲や精度を縮減したり、独自のTeX解釈器を新設したりしない。利用時の大きいチャンクは公開機能に応じて明示的に管理する。
