# ADR-0083: ContentIdで管理する連載と学習順序

## 背景

関連記事は近い内容を探す用途に向くが、読むべき次の回を保証しない。本文に前後リンクを手書きすると、続編公開後の追記忘れや、分割・並べ替え・URL変更に伴う保守作業が発生する。教育資料、技術解説、後日続きを書くメモに共通する課題である。

## 判断

利用者が2026-11-18に依頼した連番機能を、中央管理する連載registryと公開時の静的導出で実装する。所属は安定ContentId、順序は配列で管理する。カテゴリや公開日順を連番の代用にせず、個別記事の前後URLも持たせない。同じ記事の複数連載への所属を許す。

公開projectionは公開済みでindexableな内容だけを含める。非公開の予定回・見出し・件数を出さず、公開部分の番号と前後リンクを計算する。最後の公開回と連載の完結状態を分ける。存在しないIDは著者のデータ不整合なのでbuildを失敗させる。

全詳細ページの共通layoutに静的ナビゲーションを置き、連載の一覧と目次を生成する。学習コースも同じ順序モデルを使い、教育分野・対象・前提などの教育メタデータとは分けて扱う。通常の記事に専用のclient runtimeを追加しない。

## 選択肢と結果

公開日を基準にすれば古いメモの続編や学習順序が崩れる。前後IDを個別記事へ保存すればリンクの二方向整合性と循環参照の管理が必要になる。中央の順序付き配列なら並べ替えが一箇所で済み、公開状態・URL解決を共通catalogへ委ねられる。

一方、非公開回を公開すると後続の表示番号が変わることがある。表示番号を固定IDとして使用せず、リンクと記事識別には既存ContentIdを使う。部・章の階層や読了記録はこの契約に含めない。

正本は[連載契約](../../contracts/series-contract.md)。初期registryは空で、既存公開記事の所属や本文は変更しない。本ADRの採用は本番deployの実施記録ではない。
