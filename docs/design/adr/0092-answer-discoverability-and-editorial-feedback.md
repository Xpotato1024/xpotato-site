# ADR-0092: AI回答での発見性を既存の制作工程に組み込み、実記事の違和感から改善する

## 背景

Xpotatoは記事の解説だけでなく、実験・測定に基づく一次情報やブラウザツールを公開する。SEOによる検索流入だけでは、利用者がAIへ具体的な疑問を尋ね、回答の中から情報源や実行可能なツールを知る経路を十分に評価できない。

2026-11-23に、読者がAIへ尋ねそうな質問を想定し、本文の回答・根拠・実HTMLと対応させる手順をPR #243で導入した。一方、質問形の見出しや短い直接回答を機械的に増やすと、文章の不自然さ、重複、説明順序の逆転を招き得る。導入時のスキルを完成版として固定せず、実際の記事制作における結果を基に調整する必要がある。

## 判断

1. **SEOとAI回答での発見性を併用する。** 記事・ツールの代表的な読者質問を仮説化し、回答・重要条件・根拠が自然な本文と静的HTMLに存在するかを制作・監査で照合する。独自の実測や実行可能なツールなど、読者に有用な一次情報を優先する。
2. **読者向けの文章品質を上位に置く。** AIに引用されやすい表現のために不自然なFAQ、質問見出し、キーワード反復、冗長な注記、根拠のない比較を増やさない。質問数のノルマや公開用の追加メタデータは設けない。
3. **実記事で違和感が見つかったら、原因を確かめてスキルを改善する。** 具体的な見出し・段落・出力と期待する読者体験を照合し、今回のAEO/GEO規則による偏りか、元の題材・資料不足・既存の別規則・モデルの単発ミスかを切り分ける。スキル起因なら該当規則や参照例を狭く改訂し、発見された記事自体も必要に応じて修正する。
4. **改善の証拠を保持する。** 誤った出力と望ましい修正の対例を、必要なら既存のSkill evalへ追加する。既存の良い判断・独立監査・schema・公開承認を維持し、単発の違和感だけで全記事の定型・全面再執筆へ広げない。
5. **公開前と公開後の評価を分ける。** 公開前は質問に正確に答えられることを検証し、公開後は実際のAI回答における言及、URL引用、回答の正確性を観測する。推定された流入や引用を成果として捏造せず、回答が揺れることを考慮して判断する。

## 採用しない代替案

- 全記事に定数個の質問、FAQページ、専用のAI向けテキスト、全モデルの毎回テストを義務化する方式。
- AI回答への掲載率だけを最大化し、読みやすさや正確性を下げる方式。
- 違和感が見つかるたびに本文だけを場当たり的に修正し、原因となる共通のスキル規則を放置する方式。
- 一件の指摘から無関係な記事やスキルまで一括で変更する方式。

## 運用・権限

現在の具体的な制作・評価・改善手順は[AI回答での発見性](../../operations/answer-discoverability.md)が所有し、文章の優先順位は[編集方針](../../content/editorial-policy.md)に従う。ADRは採用理由・判断履歴であり、実行手順の第二正本にはしない。
