# ADR-0085: 執筆画面の分離と明示的なブロックグループ

## 背景

モバイルのレビューで、常設の7項目、ヘッダー、作業切替、各ブロックの操作と書式バーが本文領域を圧迫していた。原稿選択・連載管理を執筆画面に集める必要はない。また見出しだけを移動すると、その本文・写真を別々に移動する必要がある。

## 実装候補

原稿一覧・連載管理・記事情報・履歴・保存確認は独立した画面にし、執筆の常設ツールは構成・画像・添削にする。現在の本文と編集状態は画面切替の間も保持し、モバイルで管理画面と本文を小さく上下分割しない。

グループは共通MDX部品`<Group>`に明示する。見出しからの範囲提案は作成時の補助であり、階層の変更だけで所属を変えない。見出しを持たない画像群等もまとめられるため、公開HTMLのsectionを強制せず、rendererは子だけを出力する。

連続範囲をまとめる、新しいGroupへ子を加える、全体を移動する、解除する操作を用意する。本文は引き続きMDXが正本であり、子をASTから再生成しない。任意JSX・式や既存部品の親子制約を緩和しない。

## 検討した代案

- 見出しを常に暗黙の章とする方式は、階層編集で所属が変わり、見出しのないまとまりに使えない。
- 独自JSONの本文モデルは現在のMDX正本と外部編集の互換性を損なう。
- Callout/Detailsの流用は公開記事の意味と表示を変える。
- 文字・ボタンの縮小は読む・タップする操作を難しくする。

## 確認する振る舞い

作成・全体移動・子の編集・解除・Undo・保存再読込、CRLFと未知構文の原文保持を検証する。Groupの有無で公開の見出しID・目次・先頭本文・即時プレビューHTMLが変わらないことを確認する。320px/390px、検索時のキーボードviewport、書式操作の選択範囲保持、管理画面からの復帰を対象にする。

本記録は機能ブランチの実装候補であり、main取り込み・公開サイト配信・実iPhoneの受入れ完了を示さない。
