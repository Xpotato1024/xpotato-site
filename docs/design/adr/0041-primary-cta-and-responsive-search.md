# ADR 0041：Aの主導線採用と画面幅に応じた検索・メニュー

状態：2026-10-06のユーザー指示に基づく実装レビュー候補。Aの配置と16px角丸はユーザーが選択済みです。Bのヒーロー配置は採用せず、補助ガラスのCSSは保持します。Draft PR 65での実装・検証と、本番へのmerge・deployは別です。

## 判断と受け入れ条件

- ホームでは左を制作物の主ガラスボタン、右をAboutのテキストリンクとし、見出しの左端に主導線を揃えます。角丸と反射の縁は1rem（16px）、導線間隔は1remです。ガラスの白6%・ぼかし2px・反射の基本的な質感は維持します。
- 選択前のA/Bでは320pxの主文字背景が約4.34:1だったため、そのまま採用しません。幅360px以下だけ写真の暗い重ね背景を`#101014c2`へ強め、同じ保守的なサンプル方法で4.5:1以上を確認します。写真の切り抜き、文字、ガラスの表面は変更しません。
- `.button-glass`と`.button-glass-secondary`を組み合わせる補助ガラス指定を残します。背景、縁の反射、枠線・影、ウェイトを弱め、主部品の角丸・48px操作領域・フォーカス・無効状態を継承します。ホームのAboutには適用しません。
- デスクトップには、ラベル付きの小さな検索窓と44pxの送信ボタンを置きます。混み合う中間幅も考慮し、1180px以下では検索ページへの44pxの虫眼鏡リンクに切り替えます。本文・ヒーローの760px切り替えとは分けます。
- 同じモバイル表示でメニューを2本線の44pxボタンにします。開くと閉じる印に変わります。検索とメニューには支援技術向けの名前を付けます。
- 検索・メニューのための常駐JavaScript、UIライブラリー、React islandを追加しません。既存の経路、公開保留、検索対象、CSP、写真の非公開境界を維持します。

## 検索のURLと配信上の差

結果専用ページは既存の`/search/`、入力名は既存の`q`です。以前の検索クライアントにはURLから検索語を復元する処理がなかったため、ヘッダーの標準GETフォームと`/search/?q=...`の復元を接続します。検索・クリアで履歴を更新し、戻る・進むや結果先からの戻りでも入力・結果を復元します。空入力、0件、読み込み失敗を区別し、IME変換中のEnter・送信を確定と扱いません。古い非同期結果が新しい入力やクリアを上書きしないようにします。

この方式は検索ページ以外へ検索JS・インデックスを配信しません。一方、**検索語はブラウザー履歴と静的ページへのGETリクエストURLに含まれます**。既存の静的検索方針にある「検索語をサーバーへ送らない」という記述とは、この点で異なります。検索計算そのものは引き続きクライアント内で行い、検索API・検索語の計測・ログ設定は追加しません。凍結済みの方針や承認記録を翻訳・今回の実装によって自動改訂しません。GETの配信上の差は本番レビューで明示して扱う必要があります。

標準のフォームを選んだ理由は、全ページへの検索スクリプト追加を避け、JavaScriptなしでも検索ページへ移動できることです。検索結果は既存と同様に検索ページのJSを必要とします。入力境界には`#8f8799`を使い、明るい入力背景との識別性を確保します。クリアは標準resetボタンで、ネイティブの検索欄の消去操作にも対応します。

## メニューの標準機能と代替表示

[HTML標準のpopover](https://html.spec.whatwg.org/multipage/popover.html)と`popovertarget`を使います。ブラウザーが開閉状態と支援技術向けの[HTML-AAMで定義される暗黙のaria-expanded](https://w3c.github.io/html-aam/#att-popovertarget)を管理するため、更新されない固定のaria-expanded属性は付けません。開いた2列のナビゲーションは通常のリンクとして扱い、矢印キー専用のARIAメニューウィジェットにはしません。

対応ブラウザーではEscape、領域外クリック、呼び出したボタンへのフォーカス復帰を標準機能に任せます。`@supports selector(:popover-open)`で機能を選び、未対応時は標準detailsに同じ2本線とリンク一覧を表示します。代替表示でもリンクを失いませんが、未対応時のEscape閉鎖を保証するものではありません。メニューの表示領域は画面内で縦スクロールでき、デスクトップ幅へ戻したときに残らない表示規則を設けます。

## 検証と限界

Draft PRに記録する最新コミットで、リポジトリー・型・Astro・静的成果物・検索対象・性能容量上限と、実際のCSP下でのブラウザー操作を確認します。公開成果物の回帰検証には、ヘッダー送信、URLからの検索、クリア、戻る・進む、0件、IMEの確定抑止、静的ページのJSゼロ、Aの順序、モバイルメニューのEscape・フォーカス復帰を追加します。

非公開の写真付きレビューは、EdgeとWindowsのWebKit 26.6、1487/1280/1181/1180/1100/1024/820/390/375/320pxで確認します。初期計測で320pxはWebKit約4.81:1、Edge約4.87:1となり、選択前の約4.34:1を改善しました。文字の外接矩形内の最大背景輝度を使ったサンプルであり、字形ごとの監査やWCAG全体の適合認定ではありません。

WindowsのWebKitは実機のiPhone Safariではありません。CompositionEventによるガードの確認も、OSのIMEや実機キーボードを完全に再現するものではありません。新しいヘッダーとAを組み合わせた実機の見た目は、ユーザーによるレビューを残します。検証条件・最終結果と正確なコミットはPR 65に記録し、私用の写真・比較URL・保留記事の本文は公開PRへ添付しません。

最終の20条件の表示・操作検証、補助ガラスを含むホバー・フォーカス・押下・無効・非対応・動きを減らす設定、Edgeの実際のアクセシビリティ情報でのexpandedの開閉、Tabでの先頭リンクへの移動、CDPのIME入力、遅延した検索中のクリアの検証は成功しました。ホバーとフォーカスが重なった際に外側リングがホバー指定に負ける詳細度の問題も修正し、回帰検証へ追加しています。

同じモバイル条件で3回計測したLCP中央値は、写真付き非公開ホーム1.680s、空の検索ページ0.876s、CLSはいずれも0でした。ホームのフォントは従来と同じ4リクエスト・168,168バイト、画像は60,319バイト、JSは0です。旧ホームの1.676sとの差を速度改善・悪化の確定判断には使いません。検索ページの初期表示計測には、入力後のインデックス取得・結果描画時間は含めません。測定条件、観測値、実装ファイルのハッシュを[検証記録](../../performance/cta-header-v1.json)に保存しています。
