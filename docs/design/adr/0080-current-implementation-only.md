# ADR-0080: 現行機能を基準にした旧移行実装の撤去

## 目的

利用者が記事・メモ・ツールを扱い、CMSで編集し、安全に公開できる現行機能を維持する。旧移行工程や廃止済み方式を再現するためだけのコードをmainで保守しない。ユーザーの2026-11-17の明示承認に基づく整理であり、新機能・本番配信・R2操作は含まない。

## 判断

- 旧Phase 4〜8の変換・再現CLIと移行専用workflowを撤去する。旧版の再調査はGitの固定commitから行い、archiveコピー・互換stubを作らない。
- 保留中44記事、ContentId、旧URL対応、分類、公開媒体の来歴、現役原画像はデータとして維持する。現在のcatalog/registry/公開成果物から直接検査し、昔の移行台帳を毎回再生成しない。
- 廃止済みoperatorの実装をテスト専用に残さない。現行R2/公開経路の失敗・権限・復旧検査は維持する。
- 一時再exportを撤去し、純粋処理は共有packageを直接参照する。site固有設定を注入する薄いadapterまで無条件に削除しない。
- 通常CIは現行機能のテスト・型・契約・同一成果物の検証を並列実行する。合成receiptの16stepと90秒待機をPRごとに実行しない。外部APIの受入試験は実運用に必要な明示操作と分離する。
- JSON SchemaはZodから必要時に生成する。現行sourceと用途を持たない複製生成物はGit正本にしない。
- 現行文書のtree・CLI・状態を更新する。旧READMEや一時準備記録のコピーを恒常的な正本へ昇格しない。

## 不変条件

本文60本、公開URL、分類・検索・RSS・サイトマップ、公開画像、保留記事の非公開、CMSのGit競合/私有画像/オフライン、owner/main/manual/Environment、artifact hash・A/B/C分離を維持する。検査件数が減ることを単独で成功条件にしない。
