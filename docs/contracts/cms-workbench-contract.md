# CMS編集画面の契約

CMSは、既存のportable Markdown/MDXとregistryを編集する。本文を独自JSONへ移し替えず、サイトと同じ内容契約を使う。人が直接書く原稿もAIが作った原稿も、同じ本文・添削・保存経路で扱う。

この文書は2026-11-18の編集画面・連載実装、2026-11-19のワークフロー再編、2026-11-26の下書き・媒体引継ぎの変更候補を含む契約である。mainへの採用、本番配信、GitHub App・R2の実環境接続を示すものではない。状態の区別は[CMS実装状態](../architecture/cms-implementation-status.md)、方式の判断は[ADR-0084](../design/adr/0084-source-preserving-rich-cms-editor.md)・[ADR-0086](../design/adr/0086-cms-workflow-and-independent-registries.md)・[ADR-0093](../design/adr/0093-draft-handoff-identity.md)に記録する。

## 正本と所有者

| 対象                                 | 正本・実装の所有者                                                                               |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 本文・記事情報                       | `content/`のMarkdown/MDX。共通スキーマは`packages/content-contracts/src/content.ts`。            |
| 分類・タグ                           | `content/registry/taxonomy/`。CMSの検索・選択肢は固定commitのmanifestから読む。                  |
| 連載・学習コース                     | `content/registry/series/series.json`。[連載契約](series-contract.md)に従う。                    |
| 本文の解析・部分更新                 | `packages/editor-core/src/draft.ts`、`blocks.ts`。                                               |
| 添削の位置・提案の検査               | `packages/editor-core/src/annotations.ts`。                                                      |
| 端末の編集状態・履歴・画像           | `apps/editor/src/data/storage.ts`のIndexedDB。公開本文へ混ぜない。                               |
| 原稿に依存しない分類・連載の管理状態 | 同じIndexedDBの`workspace` store。ブランチ別の基準manifest・未保存変更・保存先を持つ。           |
| Git保存・私有同期                    | `apps/editor-api/`。公開用媒体への昇格・merge・deployはこのAPIの責務に含めない。                 |
| サイトの色・書体・本文の装飾         | `packages/design-system/`、`apps/site/src/shared/styles/`。CMS側に別のサイトテーマを複製しない。 |

`LocalDraft.id`は端末内の編集単位であり、記事の`ContentId`と別である。原稿の同一性、連載所属、媒体参照は安定したContentIdで扱う。ファイル名やタイトルを識別子にしない。

## 操作部品と文言

CMSの操作用CSSは`apps/editor/src/ui/controls.css`に共通定義を置く。サイトと共用する色・書体・操作領域・フォーカスの値は`packages/design-system`から参照し、Tailwindのutilityで通常ボタン、アイコンボタン、入力欄、チェック項目を再利用する。各画面のCSSは配置と必要な用途別の差分を持ち、同じ役割の色・枠・角丸・余白を個別に複製しない。操作用CSSを公開本文やプレビューiframeの装飾へ流用しない。

ボタンの文字は操作を表し、状態だけの表示と操作可能な表示を区別する。添削状態は文字とアイコンを併用し、色だけに依存しない。小さく見せるアイコン操作でもタップ領域を減らさない。画面見出しを言い直す説明、飾りの英語見出し、同じ場所への重複した入口は置かず、保存範囲・必要条件・失敗時の対処は省かない。

## 開始画面と作業場所

初期画面はホームとし、新規作成、既存記事の改稿、下書きの再開を分ける。下書きは端末とGitの原稿から選び、AI下書きを含めて添削から開ける。原稿の検索と種別絞り込みは編集を開始する前に行う。公開・下書きの区別は固定commitの記事目録と本文を使い、旧目録に状態がないことを公開済みの根拠にしない。

新規作成、公開原稿の改稿、Gitへ未接続の端末下書きでは、編集前に「新しいブランチ」「既存のブランチ」「この端末」の作業場所を選ぶ。Gitの作成元は取得したcommitに固定し、書込み先は`content/*`に限定する。公開原稿の改稿ではContentIdを維持して`draft:true`の編集用原稿を開き、元の公開本文をその場で変更しない。選んだ既存branchの同じpathに異なる本文があれば拒否し、選択した公開原稿の代わりにその本文を開いたり、上書きしたりしない。端末だけで作業を始める経路も残し、接続前にブランチを作ったようには表示しない。

Gitの下書き再開は、原稿を選んだ一覧のsnapshotにある`content/*`へ固定する。「添削から開く」の有無で保存先を変えず、別branch、新branch、端末への切替を再開操作に混ぜない。UIだけでなく原稿読込処理でも読み込み元・保存先の一致を検査する。開始時の選択項目が持つsnapshotを原稿・manifest取得へ渡し、その後の別branch選択や遅れた一覧応答で置き換えない。

Gitからの再取得ではContentId・原稿path・作業ブランチで既存の端末下書きを再利用する。作業ブランチのない改稿は作成元ブランチも照合する。同じIndexedDB transactionで既存確認と作成を行い、連打や別タブの取得でコピーを増やさない。本文と分類・連載が取得・保存時から変わっていなければ選択したGit版へ更新し、未保存の変更があれば内容と競合判定用の版を保持する。添削と媒体は同じ端末IDへ復元する。既存の添削は無条件に置換しない。

同じ原稿の端末コピーが複数ある場合は自動削除・統合せず、保存時刻と未保存状態、本文・添削・分類・画像の比較から継続するIDを明示選択する。別タブの変更は一覧の再取得と開始失敗時にも反映する。取得開始時に確保した下書きが別タブで削除・アーカイブされた場合、完了処理・画面への切替・そのセッションの自動保存から作り直さない。未保存の入力をメモリに保持して状態を通知する。

作業ブランチに結び付いた端末下書きも同じブランチで再開する。オフラインでもworkingBranch、取得時のbaseCommit、本文・未保存入力・添削・画像を保持し、再開だけでheadを最新化しない。Gitへまだ結び付いていない端末下書きを作業branchへ渡す場合は、本文との整合を確認し、新しい端末下書きIDと媒体IDを持つコピーを作る。旧私有Draft ID・review revision・媒体同期IDを移植せず、コピーの原稿と画像を一つのIndexedDB transactionで保存し、元データを残す。

ホーム、分類・タグ、連載、接続は原稿を開かずに利用できる。これらの画面を開いただけでは空の原稿を端末へ保存しない。原稿一覧の再読込・管理画面への移動で、編集中の本文や未保存変更を別原稿に置き換えない。

## 投稿先と記事情報

新規作成時には、記事、メモ、教育記事、固定ページ、ツール、プロダクト紹介を選ぶ。保存先は既存の5collectionを維持する。

| CMSの入口      | 保存形式                                                                       |
| -------------- | ------------------------------------------------------------------------------ |
| 記事           | `blog` collectionのMDX。                                                       |
| メモ           | `notes` collectionのMDX。                                                      |
| 教育記事       | 記事を作り、教育メタデータを付ける。既存のメモにも同じメタデータを付けられる。 |
| 固定ページ     | `pages` collectionのMDX。                                                      |
| ツール         | `tools` collectionの説明MDX。実行コードは登録済みツールの仕組みが所有する。    |
| プロダクト紹介 | `projects` collectionのMDX。                                                   |

教育記事は別の本文形式にしない。`education`に学ぶ主題、対象読者、前提知識、学習目標を記録し、公開対象だけを教育一覧へ導出する。教育の主題、通常の分類、読む順序を持つコースは独立して設定できる。既存原稿を別collectionへ移動する操作は今回のUIには含めない。

タイトルは本文の上、概要・分類・タグ・日付・検索表示などは記事情報パネルで編集する。タグは目的・技術・話題に分け、ID、表示名、別名、説明から検索できる。分類・タグの追加はregistryへの明示的な変更として保持する。未知のIDを本文に書いたことだけで自動登録しない。

プロダクトの状態・技術・リンク等は該当collectionの項目として表示する。共通スキーマに存在しても専用入力をまだ備えていない項目は、読み込んだ原稿から勝手に削除しない。下書き用のsource schemaは書きかけの概要・公開日・教育主題を許容し、公開用schemaは従来の必須条件を維持する。

## 本文の保持と編集

通常のMDXモードが扱うのは本文だけである。frontmatterを同じ入力欄へ出さない。本文だけを変更した場合、既存frontmatterのコメント、引用符、区切り、改行、BOMをそのまま残す。記事情報を変更する場合はYAMLの構造を使って該当値を更新し、その他の項目を保持する。この場合、ヘッダーの表記までbyte同一とはしない。

原稿を開く、フォーカスする、編集モードを切り替えるだけでは本文を再生成しない。リッチエディタの初期正規化を保存せず、実際に変更した領域だけを置換する。親部品の設定変更は開始タグを更新し、子の本文と未編集の空白を保持する。ブロックを移動するときも、対象の原文と区切りを使う。

| 操作の単位 | 例                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| 文字範囲   | 太字、斜体、取り消し線、インラインコード、本文中のリンク。                                                   |
| 文章の構造 | 段落、見出し、引用、箇条書き、番号付きリスト、表、区切り。                                                   |
| 複合部品   | 画像、画像グリッド、補足、手順、比較、折りたたみ、独立したリンクカード、症状と対処、棒グラフ、エンドノート。 |
| ソース     | 言語を指定したコード、数式、対応していないMDX構文。                                                          |

本文中のリンクとリンクカードは用途が違うため両方を用意する。引用・リストも、文章領域の中で構造を変える操作と、挿入メニューから作る操作を同じMarkdownへ保存する。見た目が似た専用データ形式を追加しない。

標準Markdownの脚注定義は専用の「脚注」ブロックで読み、脚注本文を編集する。本文の参照と結び付く識別子は通常の入力では変更せず、対応する参照記号を表示する。挿入と複製は文書内の定義・参照に衝突しない識別子を使い、参照段落と定義を対で追加する。未編集の定義・本文・区切りは原文を保ち、脚注を独自MDX部品へ変換しない。即時プレビューの戻りリンクは公開側と同じSVGの図形を使い、絵文字を出力しない。同じ脚注の複数参照も一意の移動先とアクセシブル名を持つ。

脚注参照を含む段落・見出し・引用・リスト・表は、参照をそのまま保持する本文入力で編集する。参照に未対応のリッチエディタへ渡してエスケープしない。脚注のない領域は既存のリッチ編集を維持する。脚注定義を補う処理はブロック表示の解析だけに使い、保存本文へ追加しない。

挿入メニューは検索、種類ごとの区切り、簡単な図示を持つ。Galleryには画像、StepsにはStepというように親子の制約に従う。ブロックの移動ハンドルは本文の横に置き、ポインターとキーボードで移動・確定・取り消しができる。サイドパネルだけで並べ替える操作にはしない。

未知の部品、未完のMDX、リッチ編集で扱えない構文は原文を残し、ソース入力へ切り替える。frontmatterそのものを解析できない場合に限り、修復用と明示してファイル全体を表示する。解析失敗を空の本文として保存しない。

MDX入力にはCodeMirrorの色分けと折り返しを使う。編集領域は端末幅に収める。PCの編集・プレビュー分割は操作で有効にし、モバイルは一つの本文領域を基本にする。上部の作業切替、外側の機能パネル、下部の状態表示と本文操作を分ける。

### 執筆画面と管理画面

ホームから原稿の作成・選択と、記事に依存しない分類・タグ・連載管理へ進む。記事情報・履歴・保存確認も本文との常時分割にしない。現在の記事の連載所属は記事情報から開ける。管理画面を開く間も現在の原稿・未保存registry・編集画面の状態を保持する。

ブロックエディタ・プレビュー・MDXは同じ階層の表示モードとし、同じSVG系統のアイコン、選択状態、アクセシブル名を持つタブとして表示する。MDXだけを独立した追加操作にしない。添削は表示モードではなく本文に紐付く作業パネルである。

執筆の常設ツールは構成・画像・添削に絞る。記事情報・履歴等は記事メニュー、保存の詳細は保存状態から開く。モバイルのパネルは本文と小さく上下分割せず、使用中のパネルに画面を使う。構成の項目・指摘の対象への移動、画像挿入の完了で本文へ戻る。

挿入は本文の境界と末尾に置き、最上部に重複する挿入バーを設けない。モバイルのタップ起動ではパレットへフォーカスし、検索入力への自動フォーカスでキーボードを出さない。キーボード起動・検索欄を選ぶ操作では検索でき、ソフトウェアキーボード表示中もvisualViewport内に候補を収める。

ブロックの常設操作は移動ハンドル・種類・操作メニューとし、上下移動、複製、ソース、削除はメニューにまとめる。書式バーは段落種別・太字・斜体・リンクを基本にし、追加書式は明示的に開く。Undo/RedoとパレットはSVGアイコンで表示する。

### 入力位置とソフトウェアキーボード

viewportの管理は`useEditorViewport`に集約する。フォーカス直後だけでなくvisualViewportのresize/scroll、選択範囲・入力・compositionの変化を受け、現在のcaretまたは入力位置を可視範囲へ戻す。入れ子のスクロール領域と固定ツールバーを考慮して必要な距離だけスクロールし、フォーカス・selection・入力本文を書き換えない。CodeMirrorのShadowRoot内は座標adapter、リッチ本文はDOM Range、通常フォームは入力位置の測定を使う。

モバイルでソフトウェアキーボードの表示を検出した間は下部の構成・画像・添削メニューを隠し、入力領域を優先する。viewport高だけを縮めて、実際のcaretが下部メニューや固定バーに隠れたままの状態を完了としない。分類・連載など管理フォームも同じ入力処理の対象とする。縮小viewportやcompositionイベントを使うブラウザー試験は実iPhone・実IMEの検証とは区別する。

### 複数ブロックのグループ

`<Group>`に見出し・文章・画像・既存部品を入れ、まとめて移動できる。グループ自体も入れ子にできる。永続境界は本文MDXに保存し、独自JSONや端末だけの所属情報にしない。公開Astroと即時プレビューは子だけを描画し、編集用の枠・名前・追加DOMを記事へ出さない。

作成方法は、新規グループの挿入、同じ親にある連続ブロックの明示選択、見出しからの範囲提案である。見出しからまとめる操作は次の同階層・上位見出し、既存グループ、ArticleEndnoteの直前までとし、記事を自動グループ化しない。解除は子をその位置へ戻し、削除とは分ける。未編集の子の記法・区切り・改行を保持する。

Group追加でGallery・Steps等の子制約やArticleEndnoteのトップレベル制約を緩めない。原文として保持できる構文と公開validatorが許可する構文を区別する。MDX外部値の反映を新しい入力として親へ再送せず、編集モードの切替・管理画面への移動を本文変更として扱わない。

構成パネルは見出しだけでなく、段落・画像・数式・コードなどを種類のSVGと短い内容で示す。グループは番号と直下のブロック数を持ち、子のブロックはインデントと線で区別する。グループ名へ子の見出しを重複表示せず、本文中のリスト項目や文字装飾を独立ブロックとして並べない。番号は現在の本文順に導出する編集上の目印であり、ContentIdや連載の回番号として保存しない。

ブロック間の挿入操作は、フォーカスしている最内側のブロックと、ポインターで指している位置に表示する。常時すべての境界へ大きな追加ボタンを置かず、非表示の操作が本文のタッチを奪わないようにする。キーボードで挿入操作へ移ったときは表示し、空の本文と末尾の追加操作は常に利用できる。見た目を小さくしても共通の操作領域を維持する。

### コードと数式

コードブロックは言語名と表示設定を編集できる。数式はサイトと同じ`math` fence、式の説明を表す`label`、任意の`print="source"`を使う。数式欄の`\sigma`はMathMLへ変換する。通常の文章に書いた`\sigma`や`tex`・`latex`というコード言語を自動で数式へ置換しない。

式の説明と印刷設定は別々に読み書きする。印刷設定を繰り返し切り替えても、説明文やTeX原文へ設定文字列を取り込まない。編集中の無効な説明文は入力欄に保持してエラーを示す。

編集画面と即時プレビューは`components/blocks/math.ts`の検査を共有し、公開側の制約に合わせたKaTeXのMathML出力を使う。無効な式、許可しないマクロ、制限を超えた式はエラーを表示し、原文を保持する。

## 原稿上の添削

本文の文字範囲・ブロック・記事全体へ指摘を付ける。記事全体は `anchor.scope:"article"` の位置なしtargetであり、部分置換の提案は拒否して手動編集と明示的解決を行う。指摘はコメントID、対象ContentId、引用、前後の文脈、利用可能ならブロック原文と相対位置を持つ。本文と指摘を分けて保存し、公開MDXや公開の内容一覧へ添削の指示を埋め込まない。

未指摘のブロックも、本文上の「指摘を追加」から新規の添削を始められる。操作へ移る前の選択範囲を保持し、選択した文章がない場合はそのブロック全体を対象にする。添削欄に対象の種類と引用を表示し、パネルを開くだけでは指摘を作成しない。入力欄へ自動フォーカスせず、閉じた際は元の操作ボタンへ戻す。

位置の再特定は、同じブロックの原文と相対位置、引用と前後文脈を順に確認する。引用が複数箇所にあり一意に決められない、本文が書き換わった、対象が消えた場合は適用を止める。近い文字列や旧offsetへの推測適用はしない。対象を失った指摘は本文と独立してopenのまま保持し、元の引用と「対象不明・未対応」を表示する。対象を明示的に付け直す場合も以前のanchor・提案を履歴へ保存する。本文の編集・移動・削除のみで解決や削除をしない。ブロックが移動しても原文が保たれていれば、そのブロック内の指摘を追跡できる。

修正案は、既存コメントIDに対する`expected`、`replacement`、理由で受け取る。`expected`が指摘時の引用と一致し、現在も同じ範囲を特定できるときだけ、その範囲を置換する。適用済みの提案を再度適用しない。未反映の指摘を解決・却下・再開でき、位置が不明になった場合は編集者が新しい範囲を指定し直せる。

本文を表示しているブロックには、位置を一意に特定できた指摘の範囲を色で示し、指摘済み・修正案あり・解決済み・反映済み・見送りを文字とアイコンでも区別する。`status:open`にproposalがある場合が「修正案あり」であり、保存上のstatusを増やさない。反映済みの範囲は置換後の文と文脈で再照合する。非編集中の安全な表示に印を付け、編集入力中のLexical/CodeMirror DOMへ装飾を差し込まない。差分は添削パネルの表示であり、`mark`・`ins`・`del`をMDXへ書き込まない。

ブロックの状態ボタンから、その箇所の現在の文章を対象に添削を開く。反映済み・解決済みの箇所では「追加の指摘」を先に示し、以前の指摘と差分は折りたたみで確認できる。追加の指摘には新しいコメントIDを割り当て、以前の反映済み記録を再開・消去しない。未反映の修正案では差分と反映操作を先に表示する。ボタンを開くだけでは本文・指摘状態を変更せず、入力欄へ自動フォーカスしてキーボードを開かない。

追加前の入力は端末下書きIDとコメントIDごとにセッション内で保持し、本文への移動・パネル切替・別原稿への移動で消さない。正式な指摘として保存するのは「指摘を追加」を押したときであり、未送信入力の再読み込み後の復元までは保証しない。パネルを閉じたときは、実際に押した起点ボタンへフォーカスを戻す。

端末では指摘をIndexedDBへ保存する。「原稿と添削を保存」は本文・分類のGit保存と、認証APIの`/draft-review`による私有Draft storeへの添削同期をまとめて行う。本文・分類に差分がなければ既存headを照合してGit更新を省略する。Git APIも同一treeのcommit生成とref更新を拒まず省略する。添削は公開Gitに含めない。添削の同期結果を端末のbaselineに保持し、同期後の入力と途中失敗は未同期として表示する。APIはContentIdと入力を検証し、`expectedRevision`が現在のreview revisionと一致する場合だけ更新する。競合は409として返し、別端末の指摘を黙って上書きしない。受信時も、同じコメントIDに異なる内容がある場合は衝突を示す。

### AIとの受け渡しの実装範囲

現時点のCMSは、本文・未解決の指摘・応答形式をJSONで書き出し、返ってきた修正案JSONを検査して取り込める。AIと人は同じGit作業ブランチ・Draft PRで本文を引き継げる。

AIの画像は、`editor:media:handoff`が準備する私有bundleから同じ原稿へ登録する。共有契約は`packages/editor-core/src/media-handoff.ts`、登録処理は`apps/editor/src/data/media-handoff.ts`が所有する。bundleはrepository、ContentId、branch、commit、原稿path、本文SHA-256、各assetIdと正規化済み画像bytes/hashを持つ。元端末の絶対pathや資格情報を含めず、Git・公開CI artifactへ保存しない。媒体の用途別制約は既存`mediaPolicy`、bundleの点数・合計容量は`mediaHandoffPolicy`を参照する。

取り込み時は本文が要求するFigure・Markdown画像・heroの集合とbundleの集合を完全一致させ、全画像を検査してから保存へ進む。登録中も現在の原稿とGit headを照合し、途中の原稿切替・本文変更・別端末のGit更新を検出したら停止する。CMSは既存の所有者session・CSRF検査の後で、Draft作成/取得、容量予約、アップロード、実bytesの再取得を行う。AIが認証済みブラウザーを利用できる場合も同じUIと登録処理を使う。

[ADR-0094](../design/adr/0094-owner-cli-draft-media.md)の登録CLIは、実行端末の既存GitHub認証を再利用する独立した入口とする。`/editor-api/cli/`ではBearerから所有者の数値IDと設定repositoryの権限を確認し、媒体manifestの照合、同じDraftの取得・作成、媒体予約・upload・readbackだけを許可する。Cookie fallback、汎用Git/分類/連載/GC操作、公開A/B/Cへの権限は追加しない。credentialはrequest処理中だけ使い、APIへ保存しない。

CLIの小さいmanifestと一件ずつの画像uploadは同じDraft storeを使う。APIでも固定Git本文と全参照画像を照合し、sourceと旧画像hash条件を予約に保持する。予約時とupload完了時のCASでrevision・旧hashを照合し、通常のブラウザーuploadを使ってCLI予約のsource検査を省略できないようにする。GitとR2の原子性は主張せず、upload前後のGit head変更は未完了として扱う。

同じassetId・hashの再実行は、保存済みbytesを確認して再利用する。異hashへの差替えはbundleの`expectedRemoteSha256`と現在の画像を照合し、媒体の更新には取得したDraft revisionを付ける。端末の未同期変更、古い旧hash、複数候補がある状態は黙って解消しない。途中までの成功を保持し、再実行で未完了分だけを登録する。最後に必要な全assetIdとhashが解決した場合だけ登録完了を示す。

Draft画像と添削の置き場はContentId・branch・sourcePathで照合する。同じ組で新しい端末IDから作成要求が来た場合は既存recordを再利用し、並列作成もCAS内で一つへ収束させる。既存IDが別原稿を指す場合や、同一ContentId・branchに複数record/異pathがある旧状態は拒否する。復元時も明示remoteDraftIdを無条件に信頼せず、この組を照合する。Draft recordのcommitはGit activityで進む値なので、画像復元でlocalのbaseCommitと同値であることは要求しない。固定commitとの一致はbundle登録と正式Astroレビューがそれぞれ検査する。

端末の媒体cacheは実bytes・MIMEとhashの版を保存し、表示用Blobをそのbytesから再構成する。既存Blob記録も読み、保存可能な環境では旧版との互換Blobを併記する。Blob固有の保存エラーを伴うtransactionのabort完了後だけ、互換Blobなしで一度再試行する。再試行でも同じID・bytesと保存先/CAS検査を使い、確定前の失敗や業務上の競合・容量不足は再試行の根拠にしない。DB version 3を維持し、旧タブの本文・添削・分類保存とアプリ更新を妨げない。互換Blobを保存できなかった画像の表示には新版CMSを使う。

cacheのmetadata一致だけでは復元を省略せず、実bytesを検査してから再利用する。読めないlegacy画像一件で全画像の取得を失敗させず、記録のidentityを保って認証済みDraftから修復する。復元先は端末下書きIDとassetIdで一意に照合し、同時復元の同値結果を再利用する。媒体の書込みと同じtransactionで保存先の下書きが同じ原稿・branchとして活動中であることも検査し、取得中の下書き削除・アーカイブ・保存先変更や画像差替え・削除は拒否する。代替テキスト・注記・出典の編集は保持する。復元のcommit後に同じ端末下書きの表示へ変更を通知する。

CMSの指摘登録を契機に、実際のAI providerやArticle Jobを自動起動する処理はまだ接続していない。自動呼出し、進捗通知、providerへの私有素材送信を実装済みとは扱わない。今後接続する際も、既存の[外部AI開示契約](external-ai-disclosure-contract.md)とArticle Jobの来歴・承認を通す。

ホームの「操作サンプルを開く」を押したときだけ、独立した端末下書き・画像・添削を作る。タイトルと概要にサンプルであることを明示し、AI下書き・添削の状態は模擬とする。実記事・Gitを変更せず、初回表示で自動挿入しない。二つのグループ、数式、言語付きコード、四つの添削表示状態を用意し、画像も外部取得のない小さなfixtureとして扱う。

## 保存・履歴・競合

端末保存、Gitへの下書き保存、公開の承認は別の状態として表示する。端末の自動保存はIndexedDBの完了を確認し、失敗を通知する。ページを離れるときにも保存を試みるが、ブラウザーの強制終了や端末の保存領域削除に対する永続性を保証しない。MDXと、画像・添削・編集中registryを含むバックアップを書き出せる。バックアップの再取込は新しい端末下書きIDで行う。

画面内の「元に戻す／やり直す」は本文・記事情報を含むsource、添削、未保存のregistry変更を対象とする。端末履歴は同じ内容の重複を避け、直近40件のスナップショットを保持する。復元前の原稿も保存する。履歴は画像ファイル、Gitのhead、リモートreview revision、執筆者区分などを巻き戻す仕組みではない。Gitの履歴とも別である。

非同期の読込・保存・復元では、開始時に対象の端末下書きIDと内容を固定する。完了時には現在開いているIDを照合し、別原稿へ本文・指摘・同期情報を混ぜない。保存中に入力された新しい本文は、送信済みの内容で置き換えない。原稿一覧の表示用スナップショットを、現在の原稿へ無条件に上書きする正本としない。

Git保存は、本文、分類・タグ追加、連載変更、導出される内容索引を同じ非force commitへまとめる。取得済みheadを照合し、古いheadへの保存は拒否する。registryは取得時の基準値も持ち、別々の連載への変更は保持し、同じ連載の衝突を編集者へ返す。競合の比較画面で本文とregistryを確認した後に再保存する。公開への昇格はこの保存操作では行わない。

### 記事を開かない分類・連載管理

分類・タグの検索と追加、連載・コースの作成・登録順は独立した管理画面で行える。記事をまだ登録していない空の連載も保存できる。管理用の下書きはIndexedDB version 3の`workspace` storeへ置き、記事の`LocalDraft`や編集履歴へ空の原稿を作って代用しない。管理画面の端末保存とGit保存も別に表示する。

認証APIの`POST /registry/save`は`branch`・`expectedHead`・`registryChanges`と任意messageを受け、許可されたtaxonomy/series操作だけを書き込む。任意path・記事source・偽のContentIdを送る経路ではない。`content/*`と取得headを照合し、非force ref更新によって保存中の競合も拒否する。連載は基準registryの一致とContentId参照を検査する。`POST /registry/pull-request`は記事IDなしで管理変更のDraft PRを作る。記事の公開、merge、媒体の公開権限は追加しない。

taxonomy変更時は公開用`editor.json`を同時に更新するが、所有者用の内容索引・連載情報を混ぜない。記事なしの管理保存は記事本文と内容索引を書き換えない。`editor-content-index.json`と連載は認証済みmanifest経路で読み、記事の公開・下書き・教育属性を作業選択へ使う。公開CMSの初期bundleに未公開の題名・ContentId・所属を組み込まない。

## プレビューと正式レビュー

| 項目             | 編集中のプレビュー                                          | 固定commitのAstroレビュー                                          |
| ---------------- | ----------------------------------------------------------- | ------------------------------------------------------------------ |
| 対象             | 現在の端末本文・記事情報・解決できる端末画像。              | Gitの固定commitと照合済みの媒体revision。                          |
| 本文の描画       | 実行しないASTから安全なHTMLを作る。                         | 正規のAstroレイアウト・部品・処理系で生成したHTML。                |
| 色・書体・CSS    | 実サイトのCSS、design-systemの値、font-faceを直接共有する。 | 対象commitの実サイトCSS・フォントを使う。                          |
| 対応できない部品 | 未表示であることを明示し、原文を保持する。                  | 正規rendererの出力で確認する。レビュー内のスクリプトは動かさない。 |
| 確認の位置づけ   | 執筆中の見た目と幅の確認。最終成果物の完全一致とはしない。  | その固定source/hashに対する正式な表示確認。編集後は失効する。      |

即時プレビューはPC 1440px、タブレット834px、スマートフォン390pxのiframe viewportを作り、その幅でCSSを適用してから表示倍率を変える。現在の倍率を含む一つの選択欄で「幅に合わせる」と「等倍（100%）」を選べるため、モバイルでもPC・タブレットの表示を確認できる。

MDXコードや任意HTMLは実行しない。未知部品、Demo、解決できないassetは代替表示と警告にする。script、フォーム、外部へのリンク遷移を許可しないiframeとCSPを使う。端末画像は与えられたassetIdとBlobを解決し、未知の外部画像を自動取得しない。

全文字種のfont-faceを共有するが、フォントをJavaScriptで一括取得しない。ブラウザーが`unicode-range`に従って必要なsubsetを読み込み、PWAも通常利用で取得した追加フォントを遅延キャッシュする。サイトの全フォントを初回offline cacheへ入れない。

即時プレビューは共有CSSを使っていてもAstroのビルド結果ではない。構文の完全な描画、公開サイト全体の構造、コードの最終装飾、登録済みツールの実際の動作は別途確認する。`DocumentEditor`は本文・画像に加え、編集途中の連載registryと所有者用の記事一覧を即時プレビューへ渡す。編集中の下書きも含む登録順で、所属・前後・目次の案内を確認できる。「登録N回」「下書きを含む登録順」と表示し、公開件数とは区別する。外部遷移は本文リンクと同様に無効とする。公開サイトの非公開除外projectionへこの編集用データを渡さない。

## 連載とサイトへの反映

CMSの連載パネルで作成、所属、読む順序、連載中・休載・完結を編集する。各回はContentIdで参照し、公開日やカテゴリから自動採番しない。本文への手動の前後リンク追加は不要になる。

サイトは公開可能で検索対象の項目だけから、全5collectionの連載名・現在の番号・前後リンク・全体目次を作る。未公開の予定回や件数を出さず、最後の公開回と完結状態を区別する。`/series/`、個別目次、教育一覧は静的に生成し、通常の記事へCMSのJavaScriptを追加しない。初期の実registryは空とし、既存記事を推測で連載へ割り当てない。詳しくは[連載契約](series-contract.md)を参照する。

## 検証の境界

原文の無変更往復、本文だけの変更、親子部品の部分更新、添削の曖昧な位置・適用済み提案、私有同期のrevision競合、Gitのhead競合、未公開情報を除く連載導出、危険なMDXの非実行を回帰検査する。単体試験とbuild成功だけで、IME、フォーカス、ドラッグ、実端末のキーボード、offline、外部認証の受入れが完了したとは扱わない。

開始画面では空原稿の自動保存がないこと、ブランチの選択・作成、改稿のContentId維持、管理用の端末状態と原稿の独立を確認する。記事なしのregistry保存はhead競合・空連載・無効参照・未知フィールド・公開manifestへの私有情報混入を検査する。キーボードの試験は実caret矩形と固定UIの重なり、selectionと本文の不変性を対象とする。実行結果は対象build・環境を特定して[CMS実装状態](../architecture/cms-implementation-status.md)と対応PRに記録する。

CodeMirrorのopen ShadowRootは、CMS内で編集用stylesheetをCSPに沿って適用するための局所的な実装である。Issue #218へ残した公開サイトのツール表示のShadow DOM隔離とは別であり、その延期課題を解消したことにはならない。

## リンク編集と部品の互換性

リンク設定では選択した本文を保持し、通常の文章ならリンク先、URL文字列なら表示文字を最初の入力対象にする。既存リンクの編集・解除も同じ入口から行う。URLだけの変更では文字装飾と子要素を保ち、表示文字を変えるときもリンク範囲だけを置換する。取消は本文を変更せず選択範囲を復元する。

新規の指摘を作る操作と、外部AIの修正案JSONを読み込む操作は分ける。ファイルの受け渡しは指摘一覧の後の「添削ファイル」に置き、読み込んだ案を本文へ自動反映しない。既存コメントID・対象原文の照合と差分確認を維持する。

比較条件、症状ごとの補足本文、折れ線・散布図をブロック操作から作れる。moduleの名前だけでなく、正しい親への追加、属性と子本文の編集、保存・再読込、プレビューと静的rendererの対応を検証する。対応表は対象revisionを持つ[ブロック点検](../audits/cms-block-coverage-20261120.md)で確認する。

## 実験グラフ・CSV取り込み

LineChartの表示は`line`、`scatter`、`analysis`。`analysis`は測定点と近似曲線を重ねる。点列の系列は従来の`label`・`points`に、任意の`role`（`observed`既定／`curve`）と`fit`を持つ。`curve`は外部で計算したXYをそのまま線で結び、サイトが推定した式や適合度を付けない。式から作る系列は`role=formula`を持ち、下記の別契約を使う。従来の折れ線・散布図のMDXを保持する。

近似は`linear`、`quad`、`poly`（3次のみ）、`exp`、`log`、`pow`、`loess`。LOESSだけ`bandwidth`（0より大きく1以下、既定0.3）を持つ。測定点と設定をMDXの正本とし、係数・曲線・R²・RMSEを同じ共通計算から再生成する。保存した古い係数を新しい測定点へ流用しない。理論式の限定した文法を除き、任意のJavaScript・Vega transformを記事入力として実行しない。

全観測を使い、観測X範囲内にのみ曲線を描く。生データの並び順・反復測定を保持する。線形等には2種類、2次・LOESSには3種類、3次には4種類以上のXが必要。LOESSの重複Xはライブラリの順序依存を避けるため明示的に拒否し、自動平均しない。対数はX>0、指数はY>0、べき乗はX>0かつY>0を全点で検査する。定義域外や計算不成立の点を除外して結果を出さない。

線形・多項式・対数の推定は元のYの最小二乗。指数はYを重みとするln(Y)の最小二乗、べき乗は対数空間の最小二乗であり、元のY空間の非線形最小二乗とは区別する。R²とRMSEは元のYで計算する。一定YのR²は算出不可、負のR²は丸めて0にしない。LOESSに単一式・係数・R²・RMSEを付けない。推定を安定させる座標変換は式とともに明示し、係数の丸め前の値も表示する。

CSVは端末内で解析し、先頭行の列名と先頭5行を確認してからX列1つ・Y列1〜6つ、系列名、測定値／計算済み曲線を選ぶ。UTF-8（BOM可）・Shift_JIS、カンマ・タブ・セミコロンを指定できる。ファイルは1,000,000 bytes以下、解析後もUTF-8換算で同上限、32列・500データ行以下。1つのグラフは理論式を含めて合計6系列。点列は各500点まで、数値の絶対値は1兆以下とする。列名を含む引用符、改行、二重引用符のエスケープを扱う。

既定は新しい系列として追加する。置換は対象系列を明示し、取り込みボタンにも置換を表示する。ファイル選択・文字コードや列の変更・プレビューでは既存値を書き換えず、「取り込む」で設定へ反映し、「設定を適用」で本文を変更する。失敗・取消では既存値を保持する。欠測、数値以外、数式、非有限値、値域外、壊れたCSVは該当する行・列を示す。空の物理行以外を読み飛ばさず、測定順を自動ソートしない。計算済み曲線は2点以上・X厳密昇順を要求する。

取り込み後のMDXには選択したXYの数値と系列・近似設定を保持する。元CSVの全列・ファイル名・バイト列の保存や公開は行わない。軸名・単位は著者が指定する。多数の点は20点ずつ編集し、図とデータ表、近似式・計算条件を同じrendererで表示する。サイトの色・文字のtokenを使い、測定点の形と近似線の破線も区別に使う。公開ページには計算用JavaScriptを配信しない。

任意物理モデルの最適化、測定誤差による重み付け、信頼区間・予測区間・誤差棒・近似の外挿はこの契約に含めない。必要なモデルの計算済み曲線は`role=curve`で取り込める。既存Vega-Lite図版CLIの入力範囲は変更せず、AIによる記事制作は同じLineChartのMDX契約を使う。[ADR-0088](../design/adr/0088-experimental-charts-and-csv.md)に判断を記録する。

### 理論式から作る曲線

`{label, role:"formula", formula:{expression,xMin,xMax,samples?}}`を点列と同じ系列配列へ保存する。`points`・`fit`との混在は拒否する。測定系列は必須ではなく、理論式だけのグラフを作り、後からCSVの測定値を追加できる。式・係数・範囲は著者が指定するもので、データからのパラメーター推定はしない。式とXの範囲を正本として保持し、描画点は毎回再計算する。

入力は`y=f(x)`の右辺で、先頭の`y=`も受け付ける。数値、`x`、`pi`、`e`、四則、括弧、累乗`^`／`**`、`sin`・`cos`・`tan`・`asin`・`acos`・`atan`・`exp`・`ln`・`log`・`log10`・`sqrt`・`abs`を使える。掛け算は`*`を明記し、三角関数はラジアン、`ln`／`log`は自然対数とする。累乗は右結合で単項マイナスより優先する。式は500文字以内、X範囲は有限で絶対値1兆以下かつ最小値<最大値。`samples`は21〜1001の整数で、既定201の初期描画密度を表す。

専用parserで文法を制限し、`eval`・`Function`・任意の識別子やプロパティ・代入・通信は許可しない。構文・評価・描画点に上限を持ち、曲がりや定義域の確認が必要な区間は上限内で細分化する。ゼロ除算、極、非実数、非有限値、計算できない範囲を点の除外で隠さず、系列全体をエラーにする。有限個の点を結ぶ数値描画であり、任意の関数に対する全区間の誤差保証ではない。通常の浮動小数点計算を使うため、大きく近い数の差などでは桁落ちが起きる。CMSの入力欄と公開の計算条件で有限精度の限界を説明する。式・描画範囲・実際の描画点数を表示し、データ表でも理論式からの計算値と測定値を区別する。R²・RMSEは付けない。

### 軸の範囲・余白

`xPadding`・`yPadding`は各軸の自動の端へ加える余白率（0〜100%、未指定は5%）で、数値文字列として保存する。通常は全系列と近似曲線を含むデータ範囲の幅に対する割合である。同一値や数値精度に近い範囲は、区別できる目盛りを持つ範囲を確保する。

`xMin`・`xMax`・`yMin`・`yMax`は各端を個別に固定する数値文字列。未指定の端は自動で、固定した端へ余白は足さない。指定値の絶対値は1兆以下で、解決後の範囲は有限・最小値<最大値を必要とする。空欄の入力は属性を省略して保存し、非数・逆転・表現できないほど狭い範囲を黙って補正しない。

表示範囲を狭くしても点列・式・近似対象は変更しない。描画領域で線と点を切り、範囲外の値がある場合は図の下に表示する。データ表は全値を保持し、近似は表示範囲外も含む全測定点から計算する。「自動に戻す」は軸の6設定だけを除き、標準の5%へ戻す。複数のグラフでもクリッピングの識別子が衝突しない。これらの計算・検証はCMS、portable MDX検証、公開Astroで共有する。[ADR-0089](../design/adr/0089-chart-formulas-and-axis-ranges.md)を参照する。
