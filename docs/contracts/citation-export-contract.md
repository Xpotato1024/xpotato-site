# Citation Export Contract

## Goal

Article Jobのvalidated source / evidenceを公開記事のcitationへ接続し、AIがURL / publication metadataを自由に捏造できないようにする。

final MDXはprovider-specific citation componentではなくportable Markdown footnoteを基本とする。

## Authoring-stage citation marker

semantic authorはURL文字列をcitationとして自由生成しない。

fixed source bundleのSource IDを参照するlogical markerだけを出す。

logical example:

```text
AstroのContent Layerでは... [@S0003]
```

複数source:

```text
... [@S0003 @S0011]
```

exact marker parserはimplementation schemaで固定する。

## Citation eligibility

SourceRecordはpublic citation eligibilityを持つ。

```ts
interface CitationMetadata {
  eligible: boolean;
  title?: string;
  publisher?: string;
  canonicalUrl?: string;
  publishedAt?: string;
  retrievedAt?: string;
  repository?: string;
  commitSha?: string;
  path?: string;
}
```

eligible=trueのsourceだけpublic citationへexportできる。

## Private / user-supplied evidence

private log、private repository、個人情報を含むsourceはcitation URLを生成しない。

記事本文で必要なら:

- `手元のログでは`
- `ローカル環境での観測では`

等、evidence classを明示する。

private source locatorをpublic footnoteへ漏らさない。

## Deterministic citation compilation

candidate materialization時にexecutorが:

1. draft citation markerをparse
2. Source IDがfixed source bundleに存在することを確認
3. sourceがcitation eligibleか確認
4. canonical metadataからfootnote definitionを生成
5. first-use order等のdeterministic ruleでfootnote labelを割り当て
6. standard Markdown footnoteへ変換

する。

AI response内のtitle / URLをcitation metadataの正本にしない。

## Final MDX example

```md
AstroのContent Layerでは...[^1]

[^1]: Astro Documentation, “Content collections”, https://docs.astro.build/...
```

actual formatting ruleはrenderer / editorial styleで固定する。

## GitHub source

GitHub code / docsをsourceにする場合、可能な限りcommit SHAへpinしたURL / identityを使用する。

public citation representationは:

- repository
- path
- commit / release

をreaderが追える形にできる。

floating `main`だけをevidence identityにしない。

## Retrieval date

current web behavior等、retrieval時点が意味を持つsourceではretrievedAtを保持する。

すべてのcitation表示に取得日を強制する必要はないが、metadata lineageには保持する。

## Citation versus link

通常のnavigation link / LinkCardとcitationを区別する。

- citation: factual claimをsupportするSourceRef
- ordinary link: reader navigation / related resource

URLが同じでもsemantic roleは異なる。

## Evidence binding

material claimにcitationがあるだけでevidence requirementを満たしたとはみなさない。

claim -> evidence -> source bindingが先にvalidであり、そのpublic representationとしてcitationを生成する。

## Citation audit

independent auditorは:

- citation markerがsourceをsupportしているか
- citationがclaim位置と対応しているか
- sourceより強いassertionになっていないか
- private source leakageがないか

を確認する。

## Footnote implementation

Astro/MDX側ではbuild-time Markdown footnote supportを利用し、citationのためにclient JavaScriptを追加しない。

必要ならremark pluginをsite build dependencyとして追加する。

## Validation

- every marker resolves known Source ID
- private/noneligible sourceをpublic URL化しない
- unknown URL generated by AI citationは禁止
- orphan footnote definition禁止
- referenced footnote definition欠落禁止
- duplicate source representationをdeterministic dedupe
