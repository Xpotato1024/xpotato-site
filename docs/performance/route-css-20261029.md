## 読み込みの責務

- `global.css`: tokens、reset、基礎書式、共通ナビゲーション、フォーム、一覧・メタデータ、共通の印刷・reduced-motion規則。
- `home.css`: ホームのhero、カルーセル、制作物・紹介区画、ガラスボタン。ホームのエントリだけがimportする。
- `search.css`: 検索フォーム・結果・状態。検索ページだけが外部linkを渡す。ヘッダーの標準GET検索は共通CSSに残す。
- `content.css`: 本文、説明、目次、数式、登録メディア、本文の印刷。ContentLayoutから読み、Primeの説明にも適用する。
- `code.css`: コード枠・色・コピーUI・印刷。実際の本文にコード枠がある場合だけ外部linkを渡す。
- `article-structure.css` / `article-modules.css`: PR121の役割を維持。後者は該当モジュールのある本文だけで読む。

ルート判定で不要なCSSをあとから削る処理は追加していない。使用するページ／部品がimportまたは`pageCssHrefs`を所有する。Vite/Astroの内容hashと共通束のキャッシュを利用し、予算ログには新たにファイル別内訳を出す。元globalの486項目をselector・祖先at-rule・宣言・important単位で独立照合し、追加／欠落は0だった。

フォントは描画済みHTMLと、実際の部品markerに対応する固定UI文字から選ぶ。検索・コードコピー・共有・Primeを全ルートへ一律に追加しない。検索結果の公開corpus文字集合は従来どおり保持する。Primeの固定文字は採用中のpackage依存から取得し、別の版番号を手で二重管理しない。元フォントbinary、Unicode範囲、書体、preload方針は変更しない。任意の利用者入力まで事前にすべてのWebフォントを取得する仕様ではなく、元のシステムfallbackは残る。

## ブラウザ検証と限界

Windows EdgeでHome、About、Blog一覧、コードNote、Search、Primeを、1440/390/320px × screen/printで比較。320pxではdark設定・reduced motionを有効化。検索結果を表示し、Primeはhydrate完了後に採取した。36条件すべてでDOM要素の主要な計算済みstyleに差分なし、横はみ出しなし。独立reviewerがPNGも比較し、23条件で完全一致、残る13条件も差分は右端4pxだけで、本文領域は画素差分0だった。Primeの390px画面とNoteの390px印刷表示も独立に目視確認した。記事の図・コードの操作・共有・メニュー・Primeの計算／中止などはrepositoryのinteraction検査を別途使う。

CDPのrule使用範囲を390px・screenで観測すると、共通束の未使用文字比率はPrimeで68.9→41.6%、Homeで56.2→41.1%。これはその画面・状態の診断値であり、印刷・hover・エラー・他ルートで必要な規則の削除根拠にはしない。`@font-face`はrule coverageが0になるため、この未使用率の評価対象から除く。

同じEdge、390×844、CPU4倍減速、150ms遅延、200,000 B/s、cache無効、各3回のローカルgzip配信でLCP/CLSを診断した。中央値はHome LCP 1,700→1,684ms、Search 816→760ms、Prime 892→928ms。CLSはそれぞれ約0.0076、0.0001、0.0003で、変化は測定ノイズの範囲。PrimeのLCP改善は主張しない。非同期処理中の総転送量は観測終了時点に依存するため、確定CSS容量と混同しない。field p75、INP、CDN、実機iOS、実印刷の検証ではない。

WindowsのAstro config読込は変更前から`detect-libc: require is not defined`で失敗。WSLの固定Linux環境でビルドした。Windows checkoutのCRLFは固定manifestのハッシュに影響したため、Git上のLFへ戻して検証した。全体試験では760成功、2件のCLI起動timeoutがあった。同じ内容の該当ファイルを単独実行すると43件すべて成功し、typecheckも成功した。閾値やtimeout設定は変更していない。最終headの全体CIをPR上の完了証拠とする。新しいlint entrypointや閾値緩和は追加しない。
