# ホームの導入と共有画像の改訂候補

## 役割を分ける

この変更はデザイン・実装のレビュー候補であり、本番採用・配信の承認ではありません。

- ヒーローの文字アニメーションは撤去し、3行の英語「Think. / Build. / Run.」を静止表示します。日本語キャッチの新しい所在はユーザー検討中であり、この候補では配置先を決めません。不要になったフッターの文字停止設定も削除します。
- 初期画面はヘッダーと工作台写真を一体にし、白いロゴ・文字・操作を写真に重ねます。スクロール24pxを超えると、同じ位置・寸法の明るいliquid glassヘッダーへ変わります。上端へ戻ると透明表示へ戻り、メニュー展開中は初期位置でも明るい面を出します。
- 参考サイト（https://jp.polene-paris.com/）の初期透明／スクロール後の独立ヘッダーを実画面で確認。借用するのは状態の構造だけで、画像・ブランド・書体・ナビ構成はXpotato自身の資産を使います。
- ヘッダーはホームだけがopt-inします。スクロール状態は小さなroute-only scriptで更新し、passive listenerとrAFでまとめ、resize・pageshow・実寸変化にも追従します。位置・高さの変形はせず、ヒーローはヘッダー高を予約します。スクリプト無効では読みやすい明るい面が残ります。
- glassは18pxの背景ぼかし、低彩度の明るい透過面、内側の細い反射と境界で表現。非対応ブラウザーは不透明面へfallbackします。OS reduced-motionでは状態変更のtransitionを止めます。
- CTAはglassをやめ、紙白の不透明面と暗い文字にします。44px以上、0.4rem角丸、近い矢印を維持し、hover・focus・activeも透過しません。
- 直下の3つの導線は、ヒーローの紹介と重複し、活動名と各一覧の内容を過度に結びつけるため撤去。サイト紹介リンクを残します。「制作物を見る」のラベルと遷移先、制作物・記事・ツールの一覧自体は変えません。
- 最下部では重複していたキャッチとサイト紹介リンクを外し、制作物・記事についての問い合わせへ案内します。
- 内部ページへの矢印はホームのカード、記事カード、各一覧で `→` に揃えます。GitHubやSNS、メールなどサイト外へ出る表示は `↗` を保持します。矢印は引き続き読み上げから除外します。

ナビゲーション構造、制作物の順序、記事・ツールの掲載上限、既存記事の公開状態は変更しません。PR163の共通ヘッダーとPrime更新は取り込まず、別のmain起点ブランチで確認します。

## 共有画像

既存の工作台写真を使い、ヒーローと同系統の低彩度・暗いグラデーション、白いロゴ、サイト名、`Think. Build. Run.` を1200×630pxに配置します。操作ボタンは入れません。写真や文字を新しいAI画像へ置き換えず、既存の凍結写真と同梱フォントからbuild時に再現できる派生物を生成します。具体的な保存・hash・配備境界は[共有画像の生成](homepage-social-card.md)を参照します。

ホームだけがこの画像をBaseLayoutへ渡し、OGとTwitterで同じURL・説明を使います。`twitter:card` は既存の条件分岐により `summary_large_image` になります。OG生成のための外部取得やブラウザーJavaScriptは追加しません。

## 検証範囲

`home-presentation.test.ts` は、説明とリンクの移動、重複キャッチの除去、内部・外部矢印の区別を検査します。`home-workshop-interaction.mjs` は正式distを使い、既存写真のdecode・レスポンシブ選択に加え、次を検査します。

- 320–1487px、短い画面、DPR 1/2/2.625/3で横はみ出し・操作領域・見出しの3行が保たれることを確認。
- 320–430pxのテスト画面で説明帯とサイト紹介が初期表示内に入り、最初の制作物カードも見え始めることを確認。すべての端末・ブラウザーの初期表示への適合を保証するものではありません。
- 静止見出し、初期／スクロール後／上端復帰のヘッダー、同じ固定位置と文書内配置、メニュー・検索・キーボード操作、reduced motion・JS無効を確認。
- 200%文字、画像503時の背景・寸法維持・メニュー操作、キーボードのfocusとサイト紹介／問い合わせへの遷移・戻るを確認。
- OG/TwitterのURL一致・寸法・alt・card種別と、同じローカル成果物内の実画像を確認。
- 既存axeと全release interactionを維持。PC・モバイル・失敗時の実画面と測定値を既存CIのquality artifactに保存。

実機Safari/Firefoxやスクリーンリーダーの受入れ、SNSサービスでのキャッシュ更新・実プレビュー、本番性能はこのブラウザーエミュレーションの成功とは別です。
