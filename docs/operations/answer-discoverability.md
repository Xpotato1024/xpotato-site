# AI回答での発見性：想定質問から本文・実HTML・公開後の回答を照合する

SEOのキーワード対策を置き換えない。読者が検索エンジンや対話AIへ自然に入力する疑問を起点に、記事・ツールの**そのページにある回答**が役立ち、誤解なく参照できる状態を作る。AEO/GEOは便宜上の呼称であり、AIによる引用・流入を保証する仕様ではない。

この手順は[一貫制作](content-production.md)の構成・内容・完成ページQAを補助する。新しいArticle Job state、公開メタデータ、必須frontmatter、外部AI provider、サイト表示部品や承認を追加しない。既存の[編集方針](../content/editorial-policy.md)と[SEO](../architecture/seo-discovery-policy.md)を優先する。

## 1. 制作前：役に立つ質問を仮説化する

- 記事は「原因・仕組み」「選び方・比較」「条件・限界」「手順・対処」、ツールは「用途」「入力・出力」「対応範囲」「同種手段との差」から、主題と読者の状況に合う**代表的な問い**だけを選ぶ。固定件数・すべての分類の網羅は求めない。
- 質問はユーザーが製品名や記事タイトルを知らなくても発する言葉で書く。例：「ブラウザだけで100桁の整数を素因数分解できるか」「投機的接触は刻み幅を小さくする方法より速いか」。
- 同義語は実際に意味が一致するときだけ扱う。質問の数を増やすために言い換えや誤字を大量生産しない。
- 現在の情報源が答えを支持しない質問は「未検証／対象外」として絞る。著者の実測、使用経験、AIによる推奨・性能比較を創作しない。

既存の非公開brief・作業メモで、必要な分だけ次の対応を保つ。毎回の入力票や公開FAQにしない。

| 問い・読者の状況 | 本文の回答箇所 | 支える根拠・実物 | 処理 |
|---|---|---|---|
| 何を質問するか | 見出し・段落・表・操作部 | 固定source／実測・実core | 既存／追加／対象外 |

## 2. 制作中：短い回答を自然な本文に統合する

- 重要な質問には、本文を読めば**何ができるか／どの条件なら成り立つか**が短い説明で分かるようにする。その直後に必要な理由、図、実測、比較、操作手順を置く。すべての節を疑問形の見出しにする必要はない。
- 条件や例外が結論を変える場合は、回答の近くに残す。冗長な但し書き・出典列挙を増やして本文を埋めない。本文を読んだ人の理解が第一。
- 記事の独自価値は検証済みの実験、ソース、工作写真、失敗条件、比較表などで示す。一般的な定義だけで一次情報を装わない。
- ツールの掲載ページは**用途→入力と操作→得られる結果→具体例→制約・対象外**の読順を優先する。手法の説明だけで利用導線が隠れないようにし、実coreで確認した例と入力上限を示す。
- 主な答えは通常の公開HTMLテキストに残す。JavaScript実行後だけ読める文、画像内だけの文字、altだけにある答え、構造化データだけのFAQに依存しない。
- 同一質問からの記事・ツールの相互導線は、実際に使い分けに役立つ場合に限る。SEO目的の大量相互リンクやAIへの命令文は入れない。

## 3. 公開前：質問と実際の候補ページを照合する

1. 採用した各質問について、対象候補の本文／静的HTMLを読み、実際の回答箇所と根拠、重要な条件を確認する。質問が見出しに存在するだけでは不十分。
2. 説明に対応する図・表・コード・実行例と、記事／ツール間の関連リンクを実表示で確認する。モデルが要約しやすいことより人間にとって正確であることを優先する。
3. 書かれていない回答、根拠の欠ける断定、実測していない数値があれば本文・実物を修正する。不要な質問を増やして帳尻を合わせない。
4. 判定は既存のbrief・PR reviewに「質問→回答位置、根拠、未検証」を短く残す。外部AIサービスの回答試験を行わなくても、この**本文の回答可能性チェック**は実施できる。

## 4. 公開後：AI回答の観測と改善

公開・indexableになったページだけを、外部サービスが実際に発見するか観測する。下書き／本人限定previewはAI経由流入の実績評価に使わない。

- 質問文、確認日・地域／言語、サービス・モデル（分かる範囲）、新規セッション等の条件を固定し、ブランド名や対象URLを質問に混ぜずに確認する。
- AIの回答での**言及**、URLの**引用／リンク**、回答内容の**正確さ**を分けて記録する。引用のないブランド言及や、自分でページを貼った結果を自然な発見と数えない。
- 必要なら「旧質問→現在の結果→不足する説明→修正箇所→再測定」を既存issue/PRへ記録する。回答が揺れるため、単一試行で掲載率・改善の因果を断定しない。モデルの挙動をサイトの自動試験PASSと混同しない。
- Search Console等の自然検索・クリック、AI回答での引用、参照トラフィックは別指標。流入が不明な場合は「未計測」とし、AI経由と推定して加算しない。外部のアクセス解析機能が使えない場合に新しい常駐システムを追加しない。
- 外部AIへの評価入力には[外部AI開示契約](../contracts/external-ai-disclosure-contract.md)を適用する。公開済みURLの確認と、未公開原稿・非公開source・社外秘ログをモデルへ送信することは異なる。非公開入力の開示権限を本手順から発行しない。

## 避ける方法と完了の考え方

- AIが引用するよう不自然に繰り返す見出し、FAQの水増し、根拠のない比較・体験談、FAQPage schemaの濫用、meta keywords、特殊なAI向けファイルの設置を標準施策にしない。
- 施策の成功を「必ず検索上位／必ずAI引用」と定義しない。公開前は**選んだ実際の問いに正確に答えるコンテンツと実表示があること**、公開後は**モデル別に観測した変化**を分けて報告する。
- 記事公開後の確認は、影響の大きい代表ページや重要改稿から優先する。毎記事で複数プロバイダーの自動API呼出しを必須にしない。
