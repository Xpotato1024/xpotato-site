# CMSのブロック機能点検

## 対象と確認の位置づけ

既存実装の基準は `d4ddf1324245859dc20711255e79eac7864e6a6d`。本記録は、その後のPR #229の作業ツリーで行う機能点検と修正対象をまとめる。clean-roomのphase-gate監査、公開承認、mainへの取り込み、本番配信の判定ではない。採用状態は[設計状態](../architecture/design-status.md)、保存とプレビューの境界は[CMS編集画面の契約](../contracts/cms-workbench-contract.md)を参照する。

公開部品の名前がCMSの一覧に存在することと、追加・編集・保存した内容が正しく表示されることを分けて確認する。ブラウザーでのタップ、選択範囲、ドラッグ、IndexedDB再読込、実iPhoneの入力は、以下の単体・Astro描画試験だけでは確認済みとしない。

## 見つかった不一致

| 対象 | 既存実装の問題 | 修正・確認する内容 |
| --- | --- | --- |
| 条件比較 | `leftLabel` / `rightLabel` と共通本文のみで、各条件の本文・写真を分けて保持できない。カードや列の表示構造もない。 | 条件ごとの `ComparisonCase` と子ブロックを使う。3条件以上の追加、変更、順序、再読込、公開描画を確認する。旧2ラベルの本文を推測で分割しない。 |
| 症状と対処 | 公開 `DiagnosticItem` は補足本文を持てるが、CMSでは子ブロックを追加・編集できない。 | 補足本文を入れ子編集へ接続し、公開側と同じ内容を保持する。 |
| 補足・注意 | `Callout` は子本文を持つが、registryの `allowsChildren` がfalse。 | registryとCMSの能力判定を一致させる。 |
| リンクカード | 公開側と即時プレビューは通常のリンク要素だけを出し、独立したカードの表示がない。 | 共通のカード構造・CSSを用い、表示名・URL・補記を保持する。外部のOG情報等を自動取得する機能とは分ける。 |
| 折れ線・散布図 | 既存の図版制作CLIでは作れるが、CMSには数値を編集する専用ブロックがない。 | 数値系列を保存する `LineChart` と静的な共通描画を追加する。既存のVega制作処理全体をCMSへ接続したとは扱わない。 |

## 独自部品の確認範囲

`content-module-coverage.test.ts` は、registry・入力スキーマと次の16部品の対応を照合する。実際の挿入テンプレートを正しい親に配置し、設定または子本文の変更、周辺原文の保持、MDXへの書出しと再読込、即時プレビューのHTMLを検査する。子を持つ11部品では、実際のReact部品が子の編集領域を描画することも確認する。

| 部品 | CMSで確認する設定・内容 | 子の追加 | 表示の確認 |
| --- | --- | --- | --- |
| Group | 見出し・本文をまとめて保持 | 本文 | 公開用の追加枠を出さず、子を表示 |
| Figure | 画像ID、説明、caption | なし | 与えた端末画像と説明 |
| Gallery | PC・モバイルの列数 | Figure | 画像の一覧と列設定 |
| Callout | 種類、見出し | 本文 | 補足・注意の構造 |
| Steps | 複数の手順 | Step | 順序付き手順 |
| Step | 手順名、結果 | 本文 | 個別の手順と結果 |
| Comparison | 独立した複数条件 | ComparisonCase | 条件ごとのカードと本文 |
| ComparisonCase | 条件名 | 本文・画像等 | 条件名と、その条件に属する内容 |
| LinkCard | 表示名、URL | なし | 独立したリンクカード |
| Details | 開閉ラベル、初期展開 | 本文 | 開閉できる詳細 |
| Demo | 登録済みツールID、表示名 | なし | 即時プレビューでは非実行の代替表示 |
| DiagnosticList | 複数の症状 | DiagnosticItem | 症状と対処の一覧 |
| DiagnosticItem | 確認・対処・理由 | 補足本文 | 本文を含む症状の説明 |
| ArticleEndnote | 補記の題名 | 安全な本文段落 | トップレベルのエンドノート |
| BarChart | 項目、数値、単位、共通最大値 | なし | 値を読める棒グラフ |
| LineChart | 複数系列の数値、軸、説明 | なし | 折れ線・散布図と正確なデータ表 |

通常のMarkdownについては、段落、見出し、箇条書き、番号付きリスト、引用、区切り、表、言語付きコード、数式の9種類を、挿入・変更・原文往復・表示まで確認する。文字装飾やリンク、表の個別操作、コード・数式設定には既存の専用試験もある。

`content-module-rendering.test.ts` は公開Astro部品を実際にコンパイルして描画する。4条件の比較、条件内の本文と画像、旧形式、ラベルのescape、折れ線と散布図、ゼロ値、元データの小数精度、無効入力の拒否を対象とする。グラフは即時プレビューと同じ静的HTMLを生成し、公開用のJavaScriptやcanvasを追加しないことを確認する。

## グラフ・図版の対応を分ける

| 機能 | 保存・描画経路 | CMSからの扱い |
| --- | --- | --- |
| 単純な項目比較 | `BarChart` の属性と数値。公開HTML。 | 専用ブロックで値を編集する。 |
| 数値X/Yの折れ線・散布図 | `LineChart` の数値系列。CMS・プレビュー・Astroで共通の静的SVGと表。 | 専用ブロックで点・系列・軸・説明を編集する。 |
| 既存Vega-Lite制作 | 許可した単一viewのline / point / bar。ローカル制作CLIがSVG・PNG・元データ・説明を生成。 | 生成した画像をFigureとして配置できる。CLIの仕様ファイルをCMSで編集・実行する接続はない。 |
| Mermaid構成図 | 制限されたflowchartをローカル制作CLIで描画。 | 生成した画像をFigureとして配置できる。専用の構成図作成UIはない。 |
| 回路・CAD・draw.io等 | 各制作処理の編集元と図版を保持し、通常の媒体経路へ渡す。 | 図版の配置・説明を編集する。元の専門形式をCMSで編集する機能ではない。 |

既存制作CLIの根拠は `ops/media/visuals/inputs.mjs`、`chart.mjs`、`cli.mjs` と[技術ビジュアル制作](../operations/technical-visuals.md)。任意のVega式、layer/facet、外部データ読込、任意のMermaid形式は既存経路でも許可していない。`mermaid` や `vega` をコード言語に設定するだけでは図へ変換しない。

新しい散布図はXの入力順や重複Xを許可する。折れ線は線で結ぶ順序を曖昧にしないため、各系列のXを厳密な昇順とする。データ表は軸目盛り用に丸めた値で置き換えない。グラフのテンプレートは合成データであり、描画成功を実測・事実確認の証拠とは扱わない。

## 残る操作上の範囲

- 脚注・参照リンクはMDXとプレビューで扱えるが、専用のGUI追加・編集はない。該当ブロックはMDX入力へ切り替える。
- Demoの登録・設定・保存と、実ツールの動作は別に確認する。即時プレビューのscript制限を緩めて検証済みにしない。
- 画像の試験fixtureはローカルの小画像。GitHub認証、Draft媒体同期、公開媒体への昇格が成功した証拠ではない。
- 全部品の設定・原文・表示の単体確認は、各入力欄を実モバイル端末で操作したことを意味しない。

## 実行結果

2026-11-20、Node 24.22.1 / npm 11.19.0 / Vitest 4.1.11で対応表・実Astro描画の2ファイル55試験が成功した。全体の単体試験は236ファイル2,099件が成功し、その後に追加した比較条件不足の回復と初回添削保存待ちの回帰試験も個別に成功した。型検査、整形、Astro check、サイトとCMSのproduction buildを実施した。

LLM-01の実Edgeで次の6系統を確認した。各試験は端末下書き・ローカル画像・合成データを使用する。

- リンク: 選択した文字の装飾と周辺本文、URLからの表示文字指定、既存リンクの変更・解除、キャンセル時の原文・選択復帰、320pxでの入力位置とTab/Shift+Tabの循環。
- 比較: パレットから3条件を作成し4条件へ追加、ラベル・本文の独立編集、条件単位の移動・削除、端末保存・再読込、PCとスマートフォンの列表示。1条件への削除時の案内と2条件への復帰、旧形式と診断補足本文も確認した。
- グラフ・プレビュー・提案読込: 2系列の点編集、空欄拒否、負数・小数、散布図の重複X、再読込、SVG・データ表、PC/タブレット/スマートフォンと倍率、320/390/1440pxのページ横溢れなし。新規指摘を作成し、ファイルから修正案を読み込み、明示的な反映まで本文が変わらないことを確認した。
- Workspace: 開始・管理・操作サンプル・添削状態・数式の反復切替・新規指摘・保存と再読込。
- Keyboard: 320/390pxのvisualViewportを模擬した14ケースでcaretの可視性と本文・選択の保持。
- Editor: rich/block/MDX、入れ子、グループと画像の移動、コード・数式・表、モバイル折り返し、端末再読込とオフライン。

比較・グラフ・リンクの画面を撮影して表示を点検した。グラフは狭い幅で文字を極端に縮小せず、グラフ内の横スクロールを使う。実iPhone/Safariのタッチ・日本語IMEは未確認である。実GitHub App/R2認証をこの検証で有効化していない。

これらは当日の作業ツリー・ビルドでの結果であり、後続変更や配布成果物へ自動的に引き継がない。同一commitのGitHub CIとSitesの反映は、それぞれ対象commit・version・成果物の照合結果をPR #229で確認する。この記録だけで公開承認とは判定しない。
