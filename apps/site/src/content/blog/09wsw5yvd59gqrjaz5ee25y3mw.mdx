ロボットの動きや接触をパソコンの中で試す物理シミュレータMuJoCoの、約3年ぶりとなるメジャーアップデートが公開されました。バージョン4.0で何が変わったのか、実際に試しながら見ていきましょう。

## MuJoCoとは？今回の更新の全体像

MuJoCoは無料・オープンソースで、関節の動きや物体との接触を速く計算することを重視したロボットシミュレータです。[［1］](https://raw.githubusercontent.com/google-deepmind/mujoco/4.0.0/README.md)

Google DeepMindが開発を進め、強化学習の実験環境「Gymnasium」の歩行タスクなどにも採用されています。ロボット制御や強化学習の研究で広く使われる、代表的なシミュレータの一つです。[［2］](https://gymnasium.farama.org/main/environments/mujoco/)[［8］](https://arxiv.org/abs/2407.08590)

<Figure asset="deepmind-logo" alt="Google DeepMindの記号ロゴと文字ロゴ" width="compact" sourceUrl="https://deepmind.google/" />

4.0.0の公開は2026年11月6日。前回の3.0.0（2023年10月18日）から約3年ぶりです。3.xでも改良は続いていましたが、4.0では**接触予測・弾塑性の追加に加え、操作画面や描画も大きな柱**になっています。[［3］](https://mujoco.readthedocs.io/en/4.0.0/changelog.html)[［4］](https://github.com/google-deepmind/mujoco/discussions/3773)

| 注目点 | 何が変わる？ |
|---|---|
| 高速な物体の接触 | 衝突を予測して、薄い壁のすり抜けを抑える |
| 柔軟体の表現 | へこみが残る塑性変形や、棒のねじりを扱う |
| 画面・描画・ブラウザ | Studio、Filament、MuJoCo Liveで調べる・見せる・試す |

## 高速な球が壁を通り抜ける――接触予測で対策

シミュレーションは時間を区切って衝突を判定します。下の球は、20 msでは壁の手前、40 msでは向こう側にあります。どちらの時刻も壁と重なっていないため、**その間の衝突を見逃す**ことがあります。

<Figure asset="contact-sampling" alt="0、20、40、60 msの離散位置。薄い輪が過去、塗りつぶした球が現在。壁は20 msと40 msの位置の間にある" title="判定の間に壁を越える" width="compact" />

従来も、時間刻みを細かくする対策はありました。ただし必要な刻みは、物体の速さ・大きさや壁の厚さによって変わります。さまざまな条件を一つの固定刻みで扱うなら、厳しい条件に合わせる必要が出ます。**刻みを細かくするほど、同じ1秒を計算する回数が増え、重くなりやすい**のが難点です。

4.0の**投機的接触**は、これからの運動を調べ、ぶつかりそうなら接触前から制約を用意する方法です。[［5］](https://mujoco.readthedocs.io/en/4.0.0/computation/speculative.html)

<Figure asset="contact-strobe" alt="MuJoCoの実描画による比較。上段OFFの球は壁を通り抜け、下段ONの球は壁の手前にとどまる" title="実シミュレーションで見るすり抜けの違い" width="compact" />

こちらは同じモデルをMuJoCoで描画した映像です。上が接触予測OFF、下がON。**時間刻みを変えずに、ONでは球のすり抜けが抑えられました。** 同じ4.0.0で接触予測だけを切り替えています。

### 刻みを細かくする方法と比べると？

同じ球と壁で、接触予測を使う方法と、刻みを細かくする方法を比べました。条件は次のとおりです。

- 球：半径10 mm、初速6 m/s
- 壁：厚さ10 mm
- 計測：Core i7-9700Kで、描画・保存を除いた物理計算のみ

刻みを細かくするといっても、どれくらい細かくすればよいのでしょうか。試してみると、**10 msや5 msでは、初期位置によってすり抜ける場合とすり抜けない場合がありました。**

| 接触予測と刻み | 元の位置 | 1 mm前へ |
|---|---|---|
| OFF・20 ms | すり抜ける | すり抜ける |
| ON・20 ms | すり抜けない | すり抜けない |
| OFF・10 ms | すり抜けない | すり抜ける |
| OFF・5 ms | すり抜けない | すり抜ける |
| OFF・2 ms | すり抜けない | すり抜けない |

初期位置を1 mmずつ120通り変えた追試でも、20 msの予測ONと2 msの予測OFFでは、すり抜けは起きませんでした。つまり、**今回確かめた条件では、接触予測によって、時間の刻みを10倍細かくした場合と同じくすり抜けを防げました。** では、計算負荷はどうでしょうか。以下では、この2つの方法の速さを比べます。

速さの指標となるRTFは、**実時間の何倍の速さで計算が進むか**を表します。1なら実時間と同じ、10なら10倍速です。[［9］](https://gazebosim.org/docs/latest/sdf_worlds/)

<BarChart title="すり抜け対策と計算の速さ" unit="RTF" max="9000" rows='[{"label":"予測OFF・20 ms","value":8930,"note":"すり抜けあり","tone":"muted"},{"label":"予測ON・20 ms","value":4790,"note":"すり抜けなし","tone":"accent"},{"label":"予測OFF・2 ms","value":1060,"note":"すり抜けなし","tone":"accent"}]' />

この例では、接触予測ONは2 msへ細かくする方法より**約4.5倍高いRTF**ですり抜けを抑えました。RTFは大きいほど速く、この差は大きいです。一方、20 msのOFFよりは遅く、予測処理そのものにも計算負荷はあります。[測定条件・元データ](https://github.com/Xpotato1024/Xpotato-Sim/blob/b4bbb7094937b20e538d1b7a0c5d33f3cc92e40c/docs/experiment-notes/2026-11-12-contact-rtf.md)

ただし、**軌道や接触力の精度が同じだと示した比較ではありません。** この球と壁でのすり抜けの有無とRTFを見た結果なので、普段使うモデルでも妥当性を確認してください。

<Details summary="追試の全結果とRTFの測定条件">

RTFは元の初期位置で計時した値です。位置を変えた追試では速度を測り直していません。

球・壁・接触の設定は固定し、初期位置だけを変えました。1 mmずらした10 ms・5 msでは、接触を検出しても球が壁の向こうへ完全に抜けています。2 msは今回確認できた条件の一つで、すり抜けを防げる最大の刻みを求めた値ではありません。

初期位置を変えた追試の結果です。各位置を3回ずつ実行し、3回とも同じ結果でした。以下は無作為抽出による確率ではなく、調べた120位置の内訳です。

| 接触予測と刻み | すり抜けた位置数 |
|---|---:|
| OFF・20 ms | 105 / 120 |
| ON・20 ms | 0 / 120 |
| OFF・10 ms | 89 / 120 |
| OFF・5 ms | 57 / 120 |
| OFF・2 ms | 0 / 120 |

| 条件 | 設定 |
|---|---|
| 球中心の初期位置 | 壁の中心を0として、−180〜−61 mmを1 mm間隔 |
| 観測時間 | 各0.1秒 |
| すり抜けの判定 | 球全体が壁の奥へ出たこと（球中心が奥面＋半径を超える） |
| 接触の設定 | 全条件で同じ。接触の時定数は5 ms |
| 再確認 | 元の位置と1 mm前の位置で、モデルを組み直しても軌道が一致 |

10 ms・5 msでのすり抜けは、接触を一度も検出しなかったという意味ではありません。[追試データ・再現スクリプト](/downloads/mujoco4-position-sweep-20261114.zip)に判定と軌道をまとめました。

RTFは追試とは別に、元の初期位置で測った値です。

- 2 msは速度計測の前に比較条件として選びました。
- 各条件18バッチの中央値です。1バッチは0.1秒のシミュレーション2,000試行、計36,000試行です。
- 描画・保存を除いた物理計算だけを測っています。実際の負荷は、接触数やソルバー設定、描画などの処理でも変わります。

</Details>

### 接触予測を有効にするには

モデルのXML（MJCF）にある`<option>`内へ追加します。

```xml
<flag speculative="enable"/>
```

何にでも使えるわけではありません。次の点を押さえておきます。

- **対象の形**：球や箱など、くぼみのない形（凸形状）同士や、平面との接触に対応します。次に紹介する柔らかい板のモデルは対象外です。
- **接触を検知する時刻**：接触の状態や押す力を読み取る、シミュレーション内の「接触・タッチセンサー」は、実際に表面が触れるより時間刻み1回分早く反応することがあります。接触を合図に制御する場合は、反応のタイミングを確認してください。[公式の制約](https://mujoco.readthedocs.io/en/4.0.0/computation/index.html#speculative-contacts)
- **予測できる運動**：次の判定まで今の速度で進むと予測するため、その間の加速は予測に含みません。[［5］](https://mujoco.readthedocs.io/en/4.0.0/computation/speculative.html)

## 曲がるだけでなく、形が残る――弾塑性に対応

ゴムのように、力を離すと元に戻るのが**弾性変形**。金属板のへこみのように、戻らず残るのが**塑性変形**です。従来の弾性モデルだけでは、後者を表せませんでした。

4.0では弾塑性が加わりました。同じ球を2枚の板に落とし、**球が離れた後の形**を比べます。

<Figure asset="plastic-comparison" alt="左の弾性板は元へ戻り、右の弾塑性板は球が離れた後もへこみが残る" title="弾性と弾塑性の違い" width="compact" />

<Figure asset="plastic-stages" alt="弾塑性板の衝突前、接触中、球が離れた後の3時刻" title="球が離れても残るへこみ" width="compact" />

この例の見どころは、**球が離れた後に、弾性側は戻り、弾塑性側にはへこみが残る**ことです。

<Details summary="変形の残り方を数値でも確認する">

見た目の違いを数値でも確かめるため、板の各頂点が初期位置から動いた量を一つの値にまとめた「変位RMS」を比べました。

| 板 | 変位RMS |
|---|---:|
| 弾性 | 0.489 mm |
| 弾塑性 | 13.594 mm |

映像の最終時刻1.8秒における、各板169頂点の3次元変位の二乗平均平方根です。最大のへこみ深さや、実物の材料を測った値ではありません。

</Details>

### 弾塑性を有効にするには

2Dの`<flexcomp>`内へ、次の`<elasticity>`を設定しています。これは抜粋で、単独で動くモデルではありません。

```xml
<elasticity young="10000000" poisson="0.3" thickness="0.0048"
            elastic2d="both" damping="0.01" yield="0.00016 0.0016"/>
```

- `yield`の2つの値：伸びと曲げの降伏ひずみ
- `elastic2d="both"`：この例で、伸びと曲げの両方を扱う設定
- 比較する弾性側：`yield`を省略

[XMLの公式説明](https://mujoco.readthedocs.io/en/4.0.0/XMLreference.html#flex-elasticity-yield)を参照してください。



柔らかい物体自体は3.0から対応していました。4.0ではこの塑性変形に加え、**棒のねじりや、輪・コイルなど曲がった自然形状の扱い**も改善されています。実物の変形量を予測するには、材料に合わせた設定が別途必要です。[［3］](https://mujoco.readthedocs.io/en/4.0.0/changelog.html)

## 画面・描画・ブラウザ利用も進化

変わったのは物理だけではありません。従来の一体型ビューアに対し、**MuJoCo Studioはパネルや機能を組み合わせて実験用の画面を作る仕組み**です。4.0で実験的な位置づけを離れ、コードやモデルの変更を反映するホットリロードも備えます。[［4］](https://github.com/google-deepmind/mujoco/discussions/3773)

描画には**Filament**を使い、材質・光・影をより豊かに表現できます。これは見え方の改善であり、描画がきれいだから物理計算も正確、という意味ではありません。[［6］](https://mujoco.readthedocs.io/en/4.0.0/programming/rendering.html)

<Figure asset="studio-live" alt="MuJoCo Liveの実画面。薄板振り子モデルと操作・モデル情報のパネル" title="ブラウザで試せるMuJoCo Live" sourceUrl="https://live.mujoco.org/?model=github:google-deepmind/mujoco/4.0.0/model/speculative/newton.xml" />

未利用なら、まず[MuJoCo Liveのデモ](https://live.mujoco.org/?model=github:google-deepmind/mujoco/4.0.0/model/speculative/newton.xml)を開くのが手軽です。インストールせずブラウザ内で動かせます。Python側で計算し、ブラウザを操作画面にするWebViewerとは別の使い方です。[［7］](https://mujoco.readthedocs.io/en/4.0.0/studio/web_viewers.html)

## Python版を4.0へアップグレードする

**Python 3.11以降が必要です。** 研究に使っている旧環境は残し、新しい仮想環境で確認することを勧めます。4.0では最小構成の`mujoco-core`と、Studio・描画を含む`mujoco-studio`へ分割され、通常の`mujoco`は両方を導入します。[［3］](https://mujoco.readthedocs.io/en/4.0.0/changelog.html)

以下の`python`は、Python 3.11以降を指すものとします。

<Steps>
<Step title="新しい仮想環境を作る">

```sh
python -m venv .venv-mujoco4
```

</Step>
<Step title="作った環境を有効にする">

使っているOSに合う方を実行します。

Windows（PowerShell）：

```powershell
.\.venv-mujoco4\Scripts\Activate.ps1
```

macOS・Linux：

```sh
source .venv-mujoco4/bin/activate
```

</Step>
<Step title="MuJoCoを導入して確認する">

```sh
python -m pip install "mujoco==4.0.0"
python -c "import mujoco; print(mujoco.__version__)"
python -m pip check
```

`4.0.0`が表示され、依存関係に問題がないことを確認します。

</Step>
<Step title="普段のモデルを同じ入力で動かす">

接触の起き方や変形を旧環境と比べます。旧形式のケーブルモデルなどには修正も必要なので、[公式の移行事項](https://mujoco.readthedocs.io/en/4.0.0/changelog.html)を確認してください。

</Step>
</Steps>

<Details summary="既存環境を更新する手順と戻し方">

新しい環境を作らずに更新する場合だけ、次の手順を使います。

1. 対象の仮想環境を有効にし、更新前のパッケージ一覧を保存します。

   ```sh
   python -m pip freeze > requirements-before-mujoco4.txt
   ```

2. 旧MuJoCoを削除し、4.0を導入します。**この操作は既存環境を変更します。**

   ```sh
   python -m pip uninstall -y mujoco
   python -m pip install "mujoco==4.0.0"
   python -m pip check
   ```

3. 上の新環境の手順と同様に、普段のモデルで動作を確認します。

### 更新前の環境へ戻す

旧環境を残していれば、そちらのPythonに戻します。既存環境を更新してしまった場合は、保存した一覧から別の環境を作り直します。

1. 更新前と同じPython版で、別の空の仮想環境を作り、有効にします。
2. 保存したファイルのある場所で、パッケージを再導入します。

   ```sh
   python -m pip install -r requirements-before-mujoco4.txt
   python -m pip check
   ```

3. 普段のモデルが更新前と同じように動くか確認します。

更新後の環境への上書きだけでは、追加された依存が残る場合があります。また、これはパッケージの再導入であり、OSや外部ライブラリを含む完全な復元ではありません。[pip freezeの説明](https://pip.pypa.io/en/stable/cli/pip_freeze/)

</Details>

## 試して感じたこと

今回の比較で、実用面で特に気になったのは投機的接触です。時間刻みを変えずに球のすり抜けが抑えられたため、接触を伴うロボット操作でも、まず普段のモデルでON/OFFを比べてみたくなる機能でした。

試す機能は、解きたい課題で選ぶと分かりやすくなります。

- **薄い対象との高速接触**が課題なら、投機的接触をON/OFFで比較する。
- **押す・曲げる作業後の形**を評価したいなら、弾塑性を設定する。

どちらも、まず普段のモデルと入力で、接触の起き方や操作後の形を確かめるところから試したいと思います。
